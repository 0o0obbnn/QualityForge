# QualityForge 阶段 4：AI 必要性、评测与治理审计 v1.0

> 日期：2026-07-30  
> 当前裁决：`AI_GOVERNANCE_PARTIAL_NOT_PRODUCTION_READY`

## 一、结论

项目已经意识到 AI 需要降级、人工确认、来源追踪和质量门禁，这比“直接生成并入库”的普通方案成熟。但当前治理仍主要依赖未经校准的置信度阈值；29 个 Skill 中只有 3 个存在标准 `evals/evals.json`，无法证明整条 AI 链的准确性、稳定性和回归能力。

AI 应限制在“提取、生成、排序、解释和建议”；确定性校验、权限、发布门禁和正式资产写入必须由规则与人工责任控制。

## 二、AI 必要性判定

| 能力 | 首选方法 | AI 作用 | 结论 |
|---|---|---|---|
| 非结构化需求要素提取 | LLM + Schema | 解析多样自然语言 | `JUSTIFIED` |
| 规则冲突和歧义发现 | 规则校验 + LLM 建议 | 扩展候选冲突 | `HYBRID` |
| 场景/用例/断言草稿 | LLM + 模板 +约束 | 提高初稿覆盖和速度 | `JUSTIFIED_WITH_GATE` |
| 来源真实性 | ID/哈希/引用校验 | AI 不负责裁决 | `DETERMINISTIC` |
| 状态可达性 | 图算法 | AI 仅辅助建模 | `DETERMINISTIC` |
| 覆盖计算 | 图查询与公式 | AI 解释缺口 | `DETERMINISTIC` |
| 正式资产批准 | 人工授权 | AI 提供 Diff 和证据 | `HUMAN_DECISION` |
| 发布阻断/放行 | 固定质量规则 + 责任人 | AI 只给风险建议 | `NO_AI_FINAL_AUTHORITY` |
| Skill 代码发布 | 构建、扫描、沙箱、人工审批 | AI 可生成草稿 | `HIGH_RISK_HITL` |
| RCA | 检索/规则/统计 + LLM | 形成候选根因和证据摘要 | `EXPERIMENTAL` |

## 三、已发现的治理冲突

1. 全局矩阵规定 Test Design 默认 L2、入库前人工终审；Test Design PRD 又规定置信度 `>0.80` 可达到 L1 并批量自动入库。两者冲突。
2. Workspace 全局默认 L2，但模块 PRD 规定 `>=0.85` 自动确立依赖图谱；错误图谱会污染下游。
3. Knowledge 默认 L2，但模块 PRD 允许 `>=0.95` 自动入向量库；模型自报分数不能证明知识正确。
4. Locator 自愈被列为可逆 L1，但自动修改定位器后重试通过可能掩盖真实 UI 缺陷；“可回滚”不等于“低业务风险”。
5. Agent 编排被列为 L1，因为“不直接改资产”；但 Tool 调用可能读取敏感数据、触发执行或间接写外部系统，应按实际动作继承最高风险，而不是按编排器自身分类。
6. 多个阈值使用 0.80、0.85、0.88、0.90、0.92、0.95，但没有校准集、可靠性曲线和阈值变更流程。

## 四、置信度问题

模型输出的“confidence”通常不是经过统计校准的正确概率。生产门禁不能只写：

```text
confidence > 0.80 → 自动通过
```

必须改为：

```text
风险等级
+ 来源完整性
+ 确定性验证结果
+ 模型校准区间
+ 历史错误率
+ 动作可逆性和影响范围
+ 强制人工检查点
→ 路由决策
```

缺少置信度、来源或风险分类时，应 fail closed，不能按高置信度处理。

## 五、推荐自治等级

| 等级 | 允许行为 |
|---|---|
| A0 | 纯确定性流程，无 AI |
| A1 | AI 只读分析和建议，不写资产 |
| A2 | AI 写草稿区，正式区需人工批准 |
| A3 | 低风险、可回滚、已校准动作自动执行并抽样复核 |
| A4 | 影响外部系统、关键资产、代码或发布，必须人工授权 |

核心价值链默认：提取/生成用 A2；验证与覆盖用 A0；正式发布用 A4。V0/V1 不开放管理员把关键写操作自行上调为全自动。

## 六、评测体系

### 6.1 分层指标

| 环节 | 必测指标 |
|---|---|
| Requirement/Rule | precision、recall、无来源编造率、冲突保留率 |
| Scenario | 规则覆盖、异常/边界/权限/状态分布、重复率 |
| Case | 可执行率、重大修改率、孤儿率、关键规则漏测率 |
| Assertion | 字段真实性、规则绑定、变异得分、假阳性/假阴性 |
| Coverage | 四维分子分母正确性、缺口清单准确性 |
| HITL | 阻断准确率、抽样命中率、审阅耗时、推翻率 |
| 整体 | 总任务耗时、采纳率、净节省、Token/金额、重放一致性 |

### 6.2 Golden Set

每个业务域至少包含正常、异常、边界、状态、权限、冲突、缺失和恶意输入。金标必须由人确认并版本化；模型、Prompt、解析器或规则版本变化时全部回放。不能用生成模型评自己的输出作为唯一评分。

### 6.3 当前证据

- IR、Scenario、Case、Assertion 已有样本级输出；
- Assertion Verifier 和 HITL Gatekeeper 有 with/without-skill 对比产物；
- 但多数 Skill 没有标准 eval 集，现有样本数量不足以估计真实错误率；
- 当前总体 Coverage Gate 失败，不能宣布端到端链已通过。

## 七、审计与可观测要求

每次 AI 调用至少记录：

- 输入来源 ID 和数据分类，而非无条件保存敏感原文；
- 模型、模型版本、Prompt/策略版本；
- 结构化输出和验证结果；
- Token、时延、重试、供应商和成本；
- Gate 决策、人工修改 Diff、批准人和原因；
- 下游消费资产及影响范围。

不应把模型隐藏思维链作为产品审计依据。应记录可展示的证据、工具调用、结构化决策摘要和最终输出。

## 八、安全停止条件

以下任一发生即停止自动生成或写入：

- 无来源业务规则或断言进入正式资产；
- 跨项目/租户内容混入；
- 敏感信息发送给未批准模型；
- 关键规则漏测且 Gate 未拦截；
- 模型升级后 Golden Set 明显回退；
- 人工推翻率持续超过阈值；
- 成本超过人工节省且无质量增益；
- Tool 调用越权或审计链断裂。

## 九、整改优先级

1. 删除“置信度超过阈值即可正式入库”的规则；
2. 统一全局和模块自治策略；
3. 对动作而非模块进行风险分级；
4. 把来源、确定性验证和强制检查点纳入路由；
5. 为核心链每个 Skill 建立版本化 eval；
6. 冻结 Golden Set 和回归门槛；
7. 建立模型/Prompt 变更审批与回滚；
8. 真实试点前进行提示注入、数据泄漏和 Tool 越权测试。

## 十、阶段裁决

`AI_GOVERNANCE_PARTIAL_NOT_PRODUCTION_READY`

可继续本机受控实验；在阈值校准、全链 eval、审计存储和强制人工门禁完成前，不应允许 AI 自动发布正式资产、修改契约、提交外部缺陷或控制发布。
