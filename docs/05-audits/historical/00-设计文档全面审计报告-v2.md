## 四、修复过程中新发现的问题

### 🆕 N-1: SkillInvocation Schema 与 PRD 字段名不一致 【一般】
- **文档**：`33-数据库Schema设计.md` L559 vs `15-PRD-SkillCenter.md` L58-59
- **证据**：
  - Schema L559: `status VARCHAR(20) NOT NULL DEFAULT 'Running'`，字段名 `status`
  - PRD L58: `execution_status VARCHAR(32) NOT NULL`，字段名 `execution_status`
  - 字段名不同（`status` vs `execution_status`），类型长度不同（VARCHAR(20) vs VARCHAR(32)）
  - 枚举值表述也有差异：Schema `Running, Success, Failed, Timeout` vs PRD `RUNNING, SUCCESS, FAILED, TIMEOUT`（大小写不一致）
- **建议**：统一为 Schema DDL 为准（大写枚举值），PRD 字段名改为 `status`。

### 🆕 N-2: ExecutionResult 和 Runner 缺少 updatedAt 【一般】
- **文档**：`04-核心领域模型.md` L541, L556, `33-数据库Schema设计.md` L315, L364
- **证据**：
  - ExecutionResult 领域模型 (L556) 和 Schema (L364) 均只有 `createdAt`/`created_at`，无 `updated_at`
  - Runner 领域模型 (L541) 和 Schema (L315) 同理
  - ExecutionResult 作为不可变执行记录可接受无 updatedAt；但 Runner 作为可变配置实体应该有时更新字段
- **建议**：至少为 Runner 补充 `updated_at`，ExecutionResult 维持不变（设计理由：写入后不可变）。

### 🆕 N-3: t_execution_task 缺少 workspace_id 外键 【严重】
- **文档**：`33-数据库Schema设计.md` L337-351
- **证据**：Schema 中 `t_execution_task` 有 `tenant_id` 和 `execution_plan_id`，但 **没有 `workspace_id`** 字段。然而：
  - Execution PRD L85: `workspace_id VARCHAR(64) FOREIGN KEY, Not Null`
  - 领域模型 ExecutionTask L515: `tenantId VARCHAR(36) NOT NULL`
  - 两者均**未声明** workspaceId 字段
  - 但 PRD L85 的原始版本有 workspace_id（审计前版本），修复后取消了
- **状态**：需确认是否故意删除（通过 execution_plan 间接关联 workspace）。如果是，PRD 中的 `workspace_id` 也应删除。

实际上，PRD 中 ExecutionJob 表 (L81-93) 有 `workspace_id`，ExecutionTask 没有。Schema 中 `t_execution_task` 可以通过 `t_execution_plan` → `workspace_id` 间接获取，不需要冗余字段。这是合理的反范式化决策。

但需要验证：PRD 的 ExecutionJob (L85) 是否有 workspace_id？让我对照确认...

从原始审计读到的 PRD L85: `workspace_id VARCHAR(64) FOREIGN KEY, Not Null` — **ExecutionJob** 有 workspace_id。但领域模型的 ExecutionTask 没有 workspaceId，这是因为它通过 executionPlanId 间接关联 Workspace。

**结论**：`t_execution_task` 无 workspace_id 是设计上的合理选择（通过 Plan 间接关联）。不是 bug。

### 🆕 N-4: ER 图简化与详细定义之间存在信息不对称 【建议】
- **文档**：`04-核心领域模型.md` ER 图实体块 (L80-230) vs 详细字段规范 (L321-847)
- **证据**：ER 图实体块仅显示 3-5 个核心字段（有意精简，L10-12 有说明）。但例如 TestCase ER 块 (L113-120) 显示 6 个字段而详细表 (L392-409) 有 14 个字段。新增的 `apiContractId` (L399) 在 ER 块中不可见。
- **状态**：文档 L10-12 明确声明此为有意设计，不算 bug。但可考虑在简化 ER 块中添加注释说明"详见第二部分"。
