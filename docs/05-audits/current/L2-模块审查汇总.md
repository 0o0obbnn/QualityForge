## 跨模块系统性缺陷（按 IEEE/Wiegers 特性维度）

### 1. Verifiable 可验证性 —— 全平台最弱（均分 ~1.8/5）🔴

**所有 10 份 PRD 零条 Given/When/Then 验收标准。** 这是 IEEE 830「Verifiable」特性的系统性崩塌。

三大核心收益指标全部不可验收：
| 指标 | 出处 | 问题 |
|---|---|---|
| "测试设计耗时缩短 80% 以上" | 11:15 | 无基线（缩短自多少？）、无测量口径、无验收门槛 |
| "AI 失败分类 15 秒内完成 + 降低 80% 排查时间" | 14:9 | 15 秒 SLA 无 LLM 推理时延论证；80% 无现状基线 |
| "CI 回归时间缩短 60% 以上" | 18:9 | 无全量回归耗时基线、无 TIA 增量口径 |
| "RAG 相关度达到 95% 以上" | 17:9 | "相关度"未定义（Recall@K？NDCG？人工一致率？）、无评测集 |

### 2. Consistent 一致性 —— 第二弱（均分 ~2.6/5）🔴

**根因：总纲 L73「用户只有一个测试工程师」是全平台一致性缺陷的源头。**
- 子模块实际涉及：审批人（16:182）、平台管理员（18:192, 19:250）、LDAP/GitHub 组织权限（19:27）、多租户隔离（19:39）
- 总纲作为顶层未约束子模块角色定义，导致一致性系统性失守
- 修复路径明确：修订总纲角色定义即可大幅改善全线一致性

### 3. Unambiguous 无歧义 —— 模糊词泛滥（均分 ~2.7/5）🟠

高频模糊词清单（需替换为可观测行为）：
- **QI 最严重**："精准分类""精准指向""海量失败""多维印证""精准修复"——"精准"无准确率定义
- **TestDesign/TestAsset**："智能提取""自动抽离""高仿真""充分覆盖""智能自愈"
- **Skill**："简单脚本""完全符合""无缝接入""齐备"

### 4. Feasible 可行性 —— 基础设施与资源错配（均分 ~3.0/5）🟠

| 重型基础设施需求 | 出处 | 单人单机可行性 |
|---|---|---|
| 分布式 Runner 集群（"数以万计用例""节点能力极值"）| 13:17 | 高风险，无降级路径 |
| K8s + gVisor/Kata 容器沙箱 | 15:137-141 | 高风险 |
| K6 并发压测 + OWASP_ZAP 安全扫描 | 15:10 | 资源开销大 |
| 5,000/50,000 API 并发、500/3,000 UI 并发 | 20:NFR | NFR 声明为 SLO Target 非实测，但仍是远景 |

**所有模块均只给 AI 降级策略，未给基础设施降级/MVP 路径。**

## 亮点（值得保持/推广）

1. **SkillCenter §4.5 沙箱安全模型**（15:132-167）—— 全套 PRD 中质量最高段落，含隔离/配额/网络/Secrets/准入/审计六子节，可作为其他模块非功能需求的范本。
2. **PlatformSettings L68 单一事实源声明** —— 显式记录历史分叉修正（SystemSecret→WorkspaceSecret），可追溯性最佳实践。
3. **TestAsset Locator 自愈三档阈值**（12:244-248）—— 量化清晰、可验证（>0.92 / 0.80-0.92 / 连续3次失败）。
4. **多数模块的降级矩阵引用** —— 以 21 号文档为单一事实源，体现一致性意识。
