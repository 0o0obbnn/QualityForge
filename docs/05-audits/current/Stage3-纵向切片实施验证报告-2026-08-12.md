# Stage 3 纵向切片实施验证报告（2026-08-12）

> 性质：8月11日独立复审后的增量实施证据。本文不改写历史审计结论，也不等同于产品验收报告。

## 1. 结论

Stage 3推荐的三项工作已完成并可重复验证：纵向切片API响应已具体化，30个Skill eval已统一，需求版本到人工审核的最小FastAPI闭环已能真实启动和调用。

当前结论是“**工程参考切片通过，可进入Stage 4持久化与真实身份验证**”，不是“平台已开发完成”。核心缺口仍是PostgreSQL/RLS、生产认证、真实模型效果、通用Runner和浏览器端到端证据。

## 3. 闭环行为

参考运行时完成以下状态序列：

```text
RequirementDocumentVersion
  → WorkItem
  → AgentSession
  → TestStrategyVersion
  → TestPlanVersion
  → 2 × TestCaseVersion
  → 4 × ReviewTask
  → PAUSED_FOR_HUMAN
  → 人工逐版本审核
  → AgentSession COMPLETED / WorkItem APPROVED
```

每个正式资产版本都计算`contentDigest`并精确绑定ReviewTask。摘要不一致返回`STALE_ARTIFACT_VERSION`；AgentIdentity尝试批准返回`FORBIDDEN`；跨租户读取按不存在处理；相同幂等键和相同请求重放同一资源，相同键不同请求返回冲突。

## 4. 安全与可信边界

- 输入DTO禁止额外字段，并约束UUID、摘要、枚举和文本长度。
- 缺少身份、租户或能力时fail-closed；正式资产审批只允许UserIdentity。
- 异常响应只返回错误码、用户可理解消息与traceId，不返回内部堆栈。
- 参考生成器是provider-neutral确定性实现，不读取、记录或外传模型API Key。
- Stage 3通过显式开发请求头模拟身份和能力；它不是JWT/OIDC认证，不能用于生产。
- 当前租户隔离是应用层参考行为；没有PostgreSQL RLS实测证据。

## 5. 尚未验证与不得宣称

| 未完成项 | 当前限制 |
|---|---|
| PostgreSQL持久化 | 状态仅在单进程内，重启丢失 |
| RLS与事务 | 目标DDL存在，但未在真实PostgreSQL执行本闭环 |
| 生产身份 | 仅开发身份头，无JWT/OIDC/JWKS与撤权传播 |
| 真实AI效果 | 14个确定性runner不代表30个Skill的模型准确率、成本或稳定性 |
| 通用Agent/Runner | 当前是固定planning workflow，不是分布式或可扩展运行平台 |
| 前端E2E | 无审核页面、浏览器旅程、可访问性或多人协作证据 |
| 全量API | 仍有58处Generic成功响应，多数目标operation未实现 |

因此不得宣称“产品通过验收”“104张目标表已经落地”“AI Agent平台已经建成”或“全部API可用”。

## 6. Stage 4推荐顺序

1. **先落同一闭环的数据最小集**：只实现Tenant/Workspace、Requirement、WorkItem、AgentSession/Trace、Strategy、Plan、Case、Review和幂等/审计所需表与迁移，不一次性创建全部104张目标表。
2. **再接真实身份与数据库隔离**：JWT/OIDC身份映射、作用域能力计算、事务边界、FORCE RLS和双租户负向测试必须一起验收。
3. **把确定性生成器抽象为provider接口**：保留确定性实现作回归基线，再接一个真实模型适配器；模型输出仍必须经过Schema、独立校验和人工硬门。
4. **补浏览器审核闭环**：只做需求查看、产物差异、逐版本审核和Trace四类最小页面，以真实API完成一条端到端旅程。
5. **通过Stage 4门后再扩模块**：基于实测迁移成本、人工修改率、误放/误阻和恢复能力，决定下一条纵向切片，而不是按模块横向铺开。

Stage 4准入门应至少包括：进程重启后数据仍在；跨租户API与直接SQL均无法越权；并发审核与幂等重试不产生双决议；真实模型故障可降级到确定性/人工路径；浏览器E2E留下可复核的版本、摘要、审批人和Trace证据。
