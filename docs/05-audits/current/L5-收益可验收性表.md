# L5 收益指标可验收性表（批次 4 产物）

> 对每个宣称的收益指标，评估是否有 BASELINE（基线）、MEASUREMENT（测量方法）、VERDICT（裁决）。
> 不可验收的收益指标 = 无法判断产品是否成功。审查日期：2026-07-30

## 逐项详析

### 指标 1：测试设计耗时缩短 80%（11:15）

> **原文**："实现需求到测试方案/用例的端到端生成，将手工编写测试设计大纲的耗时缩短 80% 以上。"

**缺失要素**：
- **基线 T0**：手工编写"测试设计大纲"的耗时是多少？按什么规模（1 份 PRD？10 条用例？）？由谁编写（初级/资深测试工程师耗时不同）？
- **测量 T1**：AI 生成耗时如何测？从点击"生成"到评审完成？还是到草稿产出？含人工评审时间吗？
- **验收门槛**：(T0−T1)/T0 ≥ 80% 的同时，用例质量如何保障？若 AI 生成快但全是垃圾用例，"缩短 80%"无意义。需补充"用例评审通过率 ≥ X%"。

**可验收版本示例**（整改建议）：
> 基线 = 3 名中级测试工程师对 5 份真实 PRD 手工编写用例，平均耗时 T0；测量 = 同 5 份 PRD 经 AI 生成 + 人工评审，耗时 T1；验收 = (T0−T1)/T0 ≥ 80% **且** 用例评审通过率 ≥ 85% **且** 漏测率（对照金标准）≤ 10%。

### 指标 2：15 秒分类 + 降低 80% 排查（14:9）

> **原文**："在 15 秒内将失败类型精准分类，将人工排查时间降低 80% 以上。"

**缺失要素**：
- **15 秒 SLA 可行性**：RCA 依赖 LLM Reasoning（14:134），当前 LLM 推理（如 GPT-4o 复杂推理）常 >15 秒。SLA 无技术论证。
- **"精准分类"准确率**：分类准确率目标未定义。95%？99%？无标注测试集，无法验证"精准"。
- **80% 基线**：现状人工排查一条失败用例平均耗时？未定义。

### 指标 3：RAG 相关度 95%（17:9）

> **原文**："使 AI Agent 设计测试用例时的信息关联相关度达到 95% 以上。"

**缺失要素**：
- **"相关度"定义**：这是最模糊的指标。可能指：top-1 准确率 / Recall@5 / NDCG@10 / 人工标注一致率（Kappa）。每种定义的测量方法和达标难度完全不同。
- **评测集**：需构建"查询→正确关联知识"的金标准集，从哪来？规模多大？

### 指标 4：CI 回归缩短 60%（18:9）

> **原文**："在保障覆盖率的前提下，使 CI 回归用例执行时间缩短 60% 以上。"

**缺失要素**：
- **基线**：当前全量回归耗时？
- **"保障覆盖率"定义**：TIA 跳过的用例，覆盖率如何确认不降？需定义 Recall（真实受影响用例的覆盖率）。
- **TIA 精准度**：TIA 的"精准选择"本身需验收（漏测率上限），否则"缩短 60%"可能以漏测为代价。

---

## 裁决

**四大核心收益指标全部不可验收**（3 个 UNSUPPORTED + 1 个 AMBIGUOUS）。

这意味着：**即使平台全部开发完成，也无法回答"我们是否达成了产品目标"**。这是产品定义层面的致命缺陷——没有成功标准，就无法判断成功。

**整改要求**：每个指标必须补齐 BASELINE + MEASUREMENT + 验收门槛（含质量约束），方可进入开发。否则开发完成后将无法验收，等于无目标开发。
