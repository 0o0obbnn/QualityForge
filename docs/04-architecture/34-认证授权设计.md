# 34-认证授权设计

> 本文定义QualityForge目标身份、作用域RBAC、审核授权、机器身份、多租户隔离和Secret安全契约。Stage 4已实现受限的本地认证Profile；OIDC、MFA、生产密钥管理和PostgreSQL RLS仍是目标设计。

Stage 4本地Profile：首位用户一次性初始化；密码使用随机盐`scrypt`；JWT校验issuer/audience/expiry并在每次请求重查SQLite成员资格；Web使用HttpOnly、SameSite=Strict Cookie和双提交CSRF；登录按客户端与邮箱限流。签名密钥仅存在进程内且重启轮换，因此持久化数据保留但用户需重新登录。AgentIdentity即使持有令牌也没有humanOnly批准资格。

## 1. 安全原则

1. 默认拒绝；认证成功不等于有权访问任何Workspace。
2. 平台、租户、Workspace、资源四级作用域显式授权，权限不因管理员身份无限向业务内容扩散。
3. 正式产出物批准是人类专属能力，受ReviewPolicy、能力、作用域和职责分离共同约束。
4. 用户权限、机器权限、Workflow节点权限、资源状态和环境条件取交集，任一Deny即拒绝。
5. 高价值动作逐次重新授权并写入不可变AuthorizationDecision和AuditLog。
6. Secret只通过引用使用，明文不进入API响应、日志、Trace、产出物或Agent上下文。

## 2. 身份类型与认证

| 身份 | 用途 | 认证方式 | 约束 |
|---|---|---|---|
| UserIdentity | Web/API人工操作 | OIDC/OAuth2授权码+PKCE；必要时MFA | 用户离职/禁用后立即失效 |
| ServiceIdentity | CI/CD、内部服务、Runner | 短时服务令牌或mTLS工作负载身份 | 不得模拟人类批准 |
| AgentIdentity | Agent Session内动作 | 由平台签发的短时、会话绑定能力令牌 | 权限不超过发起人、Agent和节点交集 |
| APIKey | 受限外部自动化 | 随机高熵密钥，只存带盐哈希 | 绑定作用域、权限、过期时间和轮换 |
| WebSocketTicket | 实时订阅 | 经REST鉴权后签发的一次性资源绑定票据 | 短时、不可复用、不扩大权限 |

JWT/令牌至少携带`iss`、`sub`、`aud`、`iat`、`exp`、`jti`和身份类型。Tenant/Workspace访问不能只依赖令牌中的角色字符串，服务端必须查询或验证当前RoleBinding及策略版本。

## 3. 信任边界

网关负责令牌校验、速率限制、清除客户端伪造的身份Header并建立内部身份上下文。下游只能在以下条件全部满足时信任网关注入上下文：

- 服务端口不可从公网或普通业务Pod绕过网关访问。
- 网关到服务使用mTLS或等价工作负载身份认证。
- 服务端验证调用方工作负载身份、令牌audience和上下文签名/完整性。
- 服务间代表用户调用使用token exchange或短时委托令牌，不透传可任意伪造的明文角色Header。

仅靠`X-Tenant-ID`、`X-User-ID`、`X-User-Roles`不构成可信授权链。

## 4. 作用域RBAC

### 4.1 内置角色模板

| 角色 | 典型作用域 | 允许职责 | 明确不自动拥有 |
|---|---|---|---|
| PlatformAdmin | PLATFORM | 平台基础设施、全局模板、租户生命周期和安全运维 | 全租户测试内容、业务批准、报告签署 |
| TenantAdmin | TENANT | 成员、租户策略、配额、共享集成和角色委派 | Workspace正式产出物批准 |
| WorkspaceAdmin | WORKSPACE | Workspace成员、环境、集成引用和常规配置 | 报告签署、质量门禁豁免、跨Workspace访问 |
| TestLead | WORKSPACE/RESOURCE | 策略/计划总体把控、风险裁决、具备授权时审核 | RBAC/Secret管理、自动越过四眼复核 |
| TestEngineer | WORKSPACE/RESOURCE | 编写/批改资产、触发执行、分析、处理Defect | 默认批准自己的产出物、权限管理 |
| ViewerAuditor | TENANT/WORKSPACE | 授权范围只读、审计和证据查看 | 写入、执行、批准、外部写入 |

角色是权限模板，不是硬编码`if role == ...`。RoleBinding明确subject、roleDefinition、scope、条件和有效期；显式Deny与humanOnly约束优先。

### 4.2 权限结构

Permission至少包含`resourceType`、`action`、`scopeTypes`、`riskLimit`、`conditionSchema`和`humanOnly`。关键权限包括：

| 能力 | humanOnly | 额外条件 |
|---|:---:|---|
| 创建/编辑草稿 | 否 | Workspace写权限 |
| 触发测试执行 | 否 | 环境、Runner、Secret及计划版本均授权 |
| 批准正式产出物 | 是 | ReviewPolicy、能力、作用域、摘要与职责分离 |
| 签署TestReport | 是 | `REPORT_SIGNOFF`能力且范围快照未陈旧 |
| 批准外部Defect写入 | 是 | `EXTERNAL_WRITE`能力、目标集成授权、负载摘要固定 |
| 质量门禁放行/豁免 | 是 | 独立能力、理由、时限和审计 |
| 发布Skill/Agent/Workflow | 是 | 代码/安全检查、Eval和治理复核通过 |
| 读取Secret明文 | 否，原则上禁止 | 仅受控执行服务短时解密，用户和Agent不直接读取 |
| 管理RoleBinding/ReviewPolicy | 是 | 不得给自己授予超出委派上限的能力 |

## 5. 审核授权与职责分离

“Approver”是ReviewTask中的临时职责，不是全局角色。每次审核必须绑定`artifactType`、`artifactId`、`artifactVersionId`和`contentDigest`。

服务端批准算法：

1. 验证调用者为活跃UserIdentity，拒绝Service/Agent身份。
2. 重新读取产出物版本与摘要；不匹配返回`STALE_ARTIFACT_VERSION`。
3. 解析适用ReviewPolicy版本、风险等级、必需阶段、人数和能力。
4. 计算调用者当前RoleBinding、作用域和条件。
5. 校验生成者与批准者分离、四眼复核、不得自批等规则。
6. 运行全部blockingChecks；未通过返回`REVIEW_REQUIRED`或具体原因。
7. 追加ReviewDecision、AuthorizationDecision和AuditLog；满足全部阶段后才由应用服务推进状态。

管理员不能通过修改客户端请求、角色Header或AI等级跳过该算法。

## 6. Agent与服务授权

Agent最终权限为：

```text
发起用户当前权限
∩ AgentVersion允许权限/Skill allowlist
∩ WorkflowVersion节点权限
∩ WorkItem授权快照
∩ 环境、集成、网络和Secret策略
− 显式Deny
− humanOnly能力
```

每次工具调用前重新校验；策略或发起人权限变化时令牌撤销或运行熔断。Agent不得继承PlatformAdmin/TenantAdmin的宽泛权限，不得持久化用户令牌或Secret，不得自行扩大委派深度。

## 7. 多租户与RLS

应用对数据库的每个事务必须注入已验证的租户、主体和必要Workspace上下文。推荐使用参数化`set_config(..., true)`，保证`SET LOCAL`语义随事务结束清除；只读查询也必须在显式事务内。

必须满足：

- 上下文缺失、格式错误或与授权决定不一致时请求终止。
- 所有租户表`ENABLE`且`FORCE ROW LEVEL SECURITY`；应用使用非owner、无BYPASSRLS身份。
- 连接池归还前事务结束；禁止会话级`SET`造成串租户。
- 平台运维跨租户查询走专用、审计、最小化的后台流程，不复用普通应用接口。
- 404/403策略避免泄漏其他租户资源是否存在。

RLS是纵深防御，不替代服务层的Workspace和资源级授权。

## 8. Secret与集成安全

- 主密钥存放于KMS/Vault，数据使用AES-256-GCM或经安全评审的AEAD加密；DEK按租户/Workspace隔离并可轮换。
- 数据库只保存密文、nonce、keyVersion和访问元数据；密钥材料不写入普通配置表。
- 执行服务以短时授权按secretRef解密，明文只存在于受控内存并尽快清除。
- Secret元数据读取与明文使用是不同权限；32号API不得返回`secretValue`。
- 外部集成限制目标域名、操作类型、Workspace和Release；每次写入使用幂等键、审核记录和负载摘要。

## 9. AuthorizationDecision与审计

以下动作必须记录只追加AuthorizationDecision：正式批准/发布、外部写入、执行启动/取消、Secret使用、角色/策略变更、Agent高风险工具调用、门禁放行/豁免。

记录至少包括主体、身份类型、动作、资源及版本/摘要、适用策略版本、RoleBinding快照、条件结果、ALLOW/DENY、原因码、traceId和时间。不得记录Secret、完整令牌或无需保留的敏感正文。

## 10. 验收标准

### AC-01 管理员不自动获得业务批准

- **Given** PlatformAdmin没有目标Workspace的业务审核RoleBinding；
- **When** 其批准TestReport或TestCase；
- **Then** 返回403并记录DENY，不因平台角色放行。

### AC-02 Agent不能批准

- **Given** Agent生成了产出物且发起人本人拥有批准权限；
- **When** Agent用会话令牌提交ReviewDecision；
- **Then** 因humanOnly被拒绝，发起人的权限不得被Agent继承用于批准。

### AC-03 防自批与陈旧批准

- **Given** 审核人与产出版本生成者相同，或提交摘要与当前版本不一致；
- **When** 请求批准；
- **Then** 返回职责分离或陈旧版本错误，不产生有效批准。

### AC-04 多租户失败关闭

- **Given** 租户上下文缺失、伪造或与资源不匹配；
- **When** 访问任一业务表；
- **Then** 服务层和RLS均拒绝，且不泄漏其他租户资源内容或存在性。

### AC-05 WebSocket不扩大权限

- **Given** 用户无目标ExecutionTask访问权；
- **When** 申请票据或连接实时流；
- **Then** 票据签发/连接被拒绝；权限在连接期间撤销时服务端主动断开。
