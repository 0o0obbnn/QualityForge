## 1. 范围与不做

## 2. 多格式摄取选型

### 2.1 决策框架（权重序）

1. **确定性优先**：同一输入必须产出同一 digest（与本项目"可复现、fail-closed"治理一致）；ML 依赖栈（模型权重、GPU 推理）降级为备选。
2. **结构保真**：标题层级可还原（需求条目切分依赖）；表格可结构化提取（业务规则抽取依赖）。
3. **依赖面最小**：与 uv 锁定兼容、纯 Python 或轻量二进制；供应链可审计。
4. **失败语义**：解析失败必须显式 REJECT（进 SourceSnapshot 的 parseStatus=FAILED），不得静默产出空文本。

### 2.2 候选对比（基于公开文档知识，全部待 PoC 验证）

| 路线            | 代表库                                | 优势                         | 风险                                       | 定位                    |
| --------------- | ------------------------------------- | ---------------------------- | ------------------------------------------ | ----------------------- |
| 分格式专用      | python-docx / pdfminer.six / openpyxl | 依赖轻、行为可预期、无 ML 栈 | 三套抽取代码、样式→语义映射自写            | **主选**                |
| 统一转 Markdown | markitdown                            | 单一输出格式、接入快         | 抽象层吞结构（标题层级可能丢失）、大依赖树 | 备选（快速预览）        |
| 统一结构化      | unstructured                          | 分块/元素类型齐备            | 依赖重、部分路径带模型下载                 | 备选                    |
| 深度文档理解    | docling                               | 表格/阅读顺序最强            | ML 栈重、与确定性优先冲突                  | 观望（L2 需要时再评估） |

**建议**：主选分格式专用库，抽取器输出统一中间表示（元素类型=标题/段落/表格/列表 + 层级 + 源偏移），SourceSnapshot 只存原文与 digest，中间表示按需重建（不落第二份真相，复用 32 号 SourceSnapshot 语义）。

### 2.3 PoC 验收（三类真实样本 × 各 3 份）

- [ ] 同文件两次解析 → 中间表示与 digest 完全一致（确定性）；
- [ ] 标题层级还原率人工核对 ≥ 90%（需求条目切分可用性判据）；
- [ ] 表格提取为结构化行（含合并单元格的显式展开规则）；
- [ ] 加密/损坏文件 → REJECT + parseStatus=FAILED，不产出空内容；
- [ ] 全链离线运行（无网络请求），供应链审计（uv lock 可复现）。

## 3. L1-L4 门禁数据模型草案（对齐 39 号 §9 链）

```
ProjectMaterial（稳定根：来源/权威等级/owner/dataClass/digest）
  └─ ProjectMaterialVersion（不可变版本：文件引用 + 解析状态 + 完整性结果）
MaterialConflict / ConflictDecision（冲突保留全版本，禁单版本裁决——不变量 2）
DlpRule（正则/字典模式 → 脱敏动作；命中未配置动作 = 阻断）
MaterialAccessPolicy（目的最小化：per-call 装载清单，默认拒绝）
OutboundApprovalLedger（出域审批台账，24 号 §3.2）
RetentionPolicy / RetentionSweep（到期清理，24 号 §2.2）
```

关键决策点：

1. `dataClass` 复用 ConversationMessage 已定枚举 `PUBLIC/INTERNAL/CONFIDENTIAL/RESTRICTED`（批次五十三 §3 schema），四处（资料/消息/证据/报告）同一分级轴。
2. 门禁顺序固化：身份权限 → 分级 → 目的最小化 → DLP → 白名单 → L3 审批 / L4 阻断 → 执行 → 输出检查 → AuditLog；任一步不可判定即默认阻断（fail-closed）。
3. AccessPolicy 是"按调用装载"而非"按角色全量"——AI 检索可及 ≠ 每次全部装载（QF-PD-028/029）。
