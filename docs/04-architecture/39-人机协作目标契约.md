## 1. 设计原则

1. 对话是可审计协作事件，不是执行授权；正式执行依据是结构化TaskCard和已批准AgentPlan。
2. 页面、WebSocket和Agent均不得直接写状态；所有高价值变化通过命令、授权和Owner应用服务完成。
3. AI可检索全部授权项目资料，每次模型调用仍按任务最小化装载并经过数据安全门禁。
4. 只有`PUBLISHED`正式版本可形成下游依赖或进入ExecutionPlanVersion。
5. 评估Agent与生产Agent权限和记录隔离，评估不能代替人工审核。

## 2. 项目资料与完整性契约

### 2.1 目标实体

| 实体 | 最小字段 | 关键约束 |
|---|---|---|
| ProjectMaterial | workspaceId、sourceType、sourceRef、currentVersionId、authorityLevel、ownerId、dataClass | UI项目仍对应Workspace，不新增Project实体 |
| ProjectMaterialVersion | materialId、version、contentDigest、capturedAt、validFrom/To、status | 不可变；同步产生新版本 |
| MaterialConflict | workspaceId、releaseId可空、left/rightVersionId、impactScope、status | 影响正式结论时必须人工裁决 |
| MaterialConflictDecision | conflictId、decision、selectedVersionIds、reason、decidedBy、decidedAt | 只追加，形成CONFIRMED证据节点 |
| CompletenessCheck | workspaceId、releaseId、purpose、requiredTypes、presentRefs、missingItems、conflicts、verdict、rulesVersion | 策划和发布分析前强制执行 |
| TestBasisBaseline | releaseId、materialVersionRefs、conflictDecisionRefs、contentDigest、status | 只有已确认基线可被正式资产引用 |

### 2.2 资料来源

V1接入`FILE/GIT/OPENAPI/POSTMAN`，文件类型至少覆盖Markdown、DOCX、PDF和表格。每次导入、同步和解析都保留来源、摘要、版本、状态和差异，不静默覆盖。

## 3. 对话、澄清、任务卡与AgentPlan

| 实体 | 最小字段 | 关键约束 |

| ConversationMessage | conversationId、actorType/id、messageType、contentRef、contentDigest、dataClass、createdAt | 只追加；敏感正文按引用存储 |
| ClarificationRequest | conversationId、agentSessionId、workItemId、question、reason、impact、requiredBy、status | `OPEN/ANSWERED/CANCELLED/EXPIRED`；提出后Session转BLOCKED |

## 4. 父子任务与阶段交接

阶段类型固定为`BASIS/STRATEGY/PLAN/CASE/AUTOMATION/EXECUTION/ANALYSIS/RELEASE_DECISION/KNOWLEDGE`。父WorkItem保存目标和整体状态；阶段WorkItem保存本阶段责任、预算和检查点。

阶段激活条件：

1. 上游正式资产版本均为`PUBLISHED`；
2. TaskContract输入摘要与当前版本一致；
3. 权限、预算、资料完整性和必要人工决定有效；
4. WorkflowTemplate版本已批准；
5. 创建`StageActivated`事件并返回明确回执。

输入变化时创建`StageInvalidated`事件，仅将受影响阶段及下游置为`STALE/BLOCKED`，不得删除历史任务或证据。

## 5. 运行命令、授权、预算和检查点

### 5.1 统一命令

`RunCommand.commandType`只允许：`PAUSE/RESUME/CANCEL/RETRY/AUTHORIZE/REVOKE`。

| 实体 | 最小字段 | 关键约束 |
|---|---|---|
| RunCommand | targetType/id、commandType、requestedBy、reason、scope、idempotencyKey、createdAt | 只追加，不直接等于生效 |
| CommandReceipt | commandId、accepted、effectiveStatus、safePointRef、attemptId、reasonCode、completedAt | 命令是否实际生效的唯一回执 |
| RuntimeAuthorization | targetId、permissionKeys、resourceScope、secretRefs、budgetDelta、validFrom/Until、status | 授权与撤销只追加决定，不泄露Secret |
| BudgetPolicy | workspaceId、workItemId可空、token/cost/time/concurrency/retryLimits、warningThresholds | 达上限自动暂停，Agent无权上调 |
| Checkpoint | targetType/id、stage、inputDigest、outputRefs、authorizationSnapshot、budgetSnapshot、createdAt | 不可变；恢复前重新预检 |

## 6. 执行与证据契约

ExecutionPlanVersion必须冻结：releaseId、publishedTestPlanVersionId、publishedTestCaseVersionIds、publishedAutomationScriptVersionIds、contractBaselineId、environmentId、dataConfigDigest、authorizationSnapshotId、budgetPolicyId和frozenBaselineDigest。

Preflight至少返回：

- 正式资产发布状态和新鲜度；
- Workspace/Release归属；
- Environment、Runner、依赖和数据可用性；
- Secret引用授权与有效期；
- 预算与并发限制；
- `PASS/BLOCKED/WAIVER_REQUIRED`及逐项证据。

人工执行与API自动化共用ExecutionTask、ExecutionResult和Evidence；通过actorType、runnerId和evidenceSource区分来源。原始证据不可UPDATE；补充说明创建EvidenceAnnotation，结论修订创建新ResultAnalysisVersion。

## 8. V1模块边界

V1必须激活本契约中与资料完整性、TaskCard/AgentPlan、Clarification、父子阶段、六类运行命令、Preflight、API Runner、统一证据、EvaluationRun和三类首页投影相关的最小面。Web UI自动化、任意Workflow设计器、全量连接器、开放Skill市场和多租户运营后置。

## 9. 数据安全门禁

任何模型、工具、文件、数据库、网络或外部系统访问先执行：

`身份与项目权限 → 数据分级 → 目的与最小范围 → DLP/脱敏 → 供应商/区域白名单 → L3审批/L4阻断 → 执行 → 输出检查 → AuditLog`

无法判断等级、脱敏失败、授权过期或目标不在白名单时默认阻断。AI和普通成员只能使用SecretRef，不得读取Secret明文。
