# 01-产品功能地图 v2.0

> QualityForge是以对话驱动、可控委派和证据闭环为核心的AI原生测试工作台。本图必须与[06-人机协作与V1业务基线](06-人机协作与V1业务基线.md)一致；术语和实体分别以03/04号权威源为准。

## 1. 产品对象关系

```text
Tenant
└── Workspace（UI展示“项目”）
    ├── Release（版本/迭代交付批次）
    ├── 来源、需求、API契约与知识
    ├── 测试策略、测试计划、用例与自动化代码
    ├── 执行计划、任务、结果与证据
    ├── 分析、Defect、报告与质量门禁
    └── WorkItem、ReviewTask与Agent运行证据贯穿全生命周期
```

Workspace是持续存在的被测产品/系统工作边界；Release是Workspace内一次有范围、有时间、有质量结论的交付批次。产品不新增与Workspace重复的Project实体。

## 2. 四个产品平面与八个能力域

产品功能按用户工作分为四个平面：项目与协作、测试生产、质量交付、平台治理。下列八个能力域用于确定实体Owner与专业工作台，不要求全部平铺为一级导航。具体导航数量由后续原型裁决；“测试产出物”不得作为一级创建模块。

| 模块 | 用户要完成的事 | AI主要承担 | 人工主要承担 | 核心产出/事实 |
|---|---|---|---|---|
| 任务看板 | 看清当前工作、阻塞、AI进度和待审核事项 | 拆分、派发建议、汇总、预检审核包 | 调整范围/优先级、处理阻塞、作审核决定 | WorkItem、ReviewTask、ReviewDecision |
| 知识库 | 管理测试依据和可复用知识 | 解析来源、规范化契约、识别冲突、提炼知识草稿 | 裁决来源冲突、审核知识和契约版本 | SourceSnapshot、RequirementDocument、APIContract、KnowledgeEntry |
| 测试策划与设计 | 形成策略、计划、场景和用例 | 编译TestingIR、生成策略/计划/用例草稿、分析覆盖 | 审核策略/计划/用例、纠正业务判断 | TestStrategy、TestPlan、TestCase |
| 自动化测试开发 | 生成和维护Web/API等测试代码 | 生成代码、检查、调试建议、Locator/Mock/数据候选 | 代码审核、关键修复、批准版本 | AutomationScript及配套资产 |
| 测试执行 | 安全、可复现地运行测试并收集证据 | 冻结资产版本、调度Runner、重试、采集日志/证据 | 批准高风险首跑、处理环境例外 | ExecutionPlan、ExecutionTask、ExecutionResult、Evidence |
| 质量分析与缺陷 | 把执行事实转成质量判断和交付物 | 聚类、RCA、Defect/报告草稿、门禁建议 | 审核分析/Defect/报告、外部写入和发布判断 | ResultAnalysis、Defect、TestReport、QualityGate |
| AI Agent中心 | 管理AI能力、职责、Workflow和效果 | 执行受限Workflow、留Trace、运行Eval | 发布能力/权限、审核评测、处理越权和降级 | Skill、Agent、Workflow、Trace、Eval |
| 平台管理 | 管理Workspace、Release、环境、集成、权限和审计 | 配置预检、最小权限建议、异常提示 | 安全配置、成员/权限、Secret和基础设施管理 | Workspace、Release、RBAC、Environment、Integration、AuditLog |

## 3. 人机协作主旅程

```text
选择/默认进入最近更新项目
  → 在首屏对话中说明目标、范围和约束
  → AI读取已授权的项目全量资料并报告完整性/冲突
  → 人工补充或裁决，固化测试依据基线
  → 确认AgentPlan与TaskCard
  → 来源固化
  → AI生成策略/计划草稿
  → 人工审核
  → AI生成用例与自动化代码草稿
  → 人工审核/批改
  → AI编排执行并收集不可变结果
  → AI生成分析、Defect和报告草稿
  → 人工审核/签署/外部写入批准
  → 已审核经验回流知识库
```

首屏是项目驾驶舱与对话入口；任务看板承载结构化工作，ReviewTask是人工控制点，Agent Trace是AI行为证据。阶段只能由显式激活契约交接，不得因为上一步“运行成功”自动进入下一阶段。

## 4. 八类正式产出物

| 正式产出物 | Owner模块 | 人工责任 |
|---|---|---|
| TestStrategy | 测试策划与设计 | 认可范围、风险和测试方法 |
| TestPlan | 测试策划与设计 | 认可里程碑、资源、依赖和验收准则 |
| TestCase | 测试策划与设计 | 认可步骤、预期和业务覆盖 |
| AutomationScript | 自动化测试开发 | 完成代码审核和可执行性判断 |
| ResultAnalysis | 质量分析与缺陷 | 认可对执行事实的解释和限制 |
| Defect | 质量分析与缺陷 | 认可问题成立、严重度、证据和外部同步内容 |
| TestReport | 质量分析与缺陷 | 签署范围、结论和风险披露 |
| KnowledgeEntry | 知识库 | 认可适用范围、失效条件和来源 |

每类正式产出物采用稳定根+不可变版本；ReviewTask必须绑定精确versionId和contentDigest。AI、管理员开关和机器检查均不能代替人类批准。

## 5. 设计解决的痛点

| 痛点 | 产品机制 | 价值 |
|---|---|---|
| 工作分散、AI运行不透明 | 任务看板统一工作项、运行和审核队列 | 降低切换、等待和追问成本 |
| 测试依据版本混乱 | 来源快照、契约版本和基线 | 结论可追溯、可复现 |
| 策略/计划/用例手工重复 | AI生成草稿+人工集中审核 | 提高产出速度并保留专业判断 |
| 自动化代码维护成本高 | 独立代码工作台、版本和代码审核 | 让代码成为可治理正式资产 |
| 执行结果和AI推断混在一起 | ExecutionResult只追加，分析独立版本化 | 防止推断污染事实 |
| 提Bug、分析和报告重复 | AI组织证据与生成草稿 | 缩短质量反馈周期 |
| AI权限和效果不可控 | allowlist、Trace、Eval、降级和humanOnly | 可控、可审计、可持续改进 |

## 6. 版本演进

| 阶段 | 定位 | 产品承诺 |
|---|---|---|
| V0 | 设计和Gate 0原型 | 契约、治理和样例可审查，不冒充可用产品 |
| V1 | 单Workspace真实业务闭环 | 首屏对话、项目驾驶舱、真实API链、手工测试记录、独立评估Agent和人工硬门禁 |
| V2 | 团队协同和集成增强 | 多Runner、外部集成、质量门禁、知识反馈和稳定运营 |
| V3 | 企业规模和更高代理能力 | 更大规模、更丰富能力与L3编排，但不取消人工硬门 |

详细范围、非目标和准入门见22号版本规划。
