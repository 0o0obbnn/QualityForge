# 20-非功能需求

> 本文定义可验收的非功能属性和建立SLO的方法。当前无运行系统、容量基线或生产流量，因此不把未经实测的并发、延迟、可用性或AI准确率写成已承诺指标。各版本先测基线，再批准目标值。

## 1. 验收方法

每个NFR必须记录：`metricKey`、用户旅程/工作负载、数据规模、环境、测量窗口、统计口径、基线、目标、错误预算、采集方式、责任人和版本。没有这些字段的数字只算候选，不构成交付门禁。

## 2. 性能与容量

| 对象 | 必测指标 | 分层维度 |
|---|---|---|
| Web | LCP/INP/CLS、首个可操作时间、错误率 | 页面、设备、网络、冷/热缓存 |
| REST API | P50/P95/P99、吞吐、错误率、饱和度 | operationId、读写、数据量、租户 |
| AI步骤 | 首个结果/完整结果延迟、成功成本、超时和人工接管率 | interventionKey、模型/Prompt/Skill/Workflow版本 |
| 执行调度 | 排队时间、启动时间、有效并发、资源利用率 | Runner能力、测试类型、环境 |
| 证据/报告 | 上传、索引、聚合和下载延迟 | 制品大小、结果数、保留层级 |

V1开发前建立单Workspace试点负载模型；每个版本的目标值以压测报告批准，不从旧规划继承任意`50/200/5000`等数字。

## 3. 可用性与韧性

- 按用户旅程定义SLI，不以“进程存活”替代可用性。
- 外部LLM、Defect、Git、CI、KMS和Runner均设置超时、预算、熔断和明确降级，不无限重试。
- WorkItem、ExecutionTask和AgentSession支持取消、重放和幂等；重放创建新attempt并保留旧证据。
- 消息采用至少一次传递时，消费者以稳定事件ID/幂等键去重。
- 定期演练Runner失联、队列积压、数据库故障、对象存储故障、LLM限流和外部集成超时。
- RTO/RPO在部署拓扑和业务等级明确后批准；V0只定义恢复步骤和证据要求。

## 4. 数据一致性与可追溯性

1. 正式产出物使用稳定根+不可变版本；ReviewTask绑定versionId+contentDigest。
2. ExecutionResult、Evidence、ReviewDecision、AuthorizationDecision、AuditLog和Agent Trace只追加。
3. 异步操作返回WorkItem/attempt资源，不以HTTP 200掩盖后台失败。
4. API写操作使用Idempotency-Key；相同键不同payload返回冲突。
5. 跨域变更优先使用本地事务+事件/Outbox和可补偿Workflow；不预设每个流程都需要Saga。
6. 删除默认归档；存在历史引用时阻止物理删除并返回依赖。
7. 追踪链至少覆盖SourceSnapshot→TestingIR/Rule→Strategy/Plan/Case→Script→Execution→Analysis/Defect/Report→Review。

## 5. 安全与隐私

| 领域 | 强制要求 |
|---|---|
| 认证 | OIDC/OAuth2或短时工作负载身份；令牌audience/expiry/jti验证 |
| 授权 | 四级作用域RBAC、humanOnly、显式Deny和逐次AuthorizationDecision |
| 多租户 | 服务层授权+PostgreSQL ENABLE/FORCE RLS，应用身份无BYPASSRLS |
| Secret | KMS/Vault+AEAD、只传引用、短时解密、轮换和使用审计 |
| Agent | 默认零网络/无Secret/无外部写入；权限取交集；工具调用前授权 |
| 供应链 | 锁定依赖、SBOM、签名/来源、SAST/SCA、恶意Skill隔离 |
| 证据 | 分类分级、最小采集、脱敏、访问控制、保留/删除策略 |
| 日志 | 不记录令牌、Secret、隐藏思维链或不必要正文；保留决策摘要和引用 |

安全测试至少覆盖跨租户、IDOR、角色/作用域提升、自批、陈旧批准、Secret泄漏、SSRF/出站绕过、提示注入、恶意文件和依赖供应链。

> 合规与隐私详设（数据驻留/被遗忘权、保留期限数字、LLM 出站审批、指标数据字典、permissionKey 目录）见 [24-合规与隐私设计](24-合规与隐私设计.md)。

## 6. AI质量与治理

- 每个介入点有Golden Set、人工基线、指标定义、版本和适用范围。
- 分别报告机器检查、独立验证和人工验收，不把任一层替代另一层。
- 重点监控人工修改率、误放、误阻、越权、幻觉引用、降级、成本和延迟。
- 无有效版本化校准记录时AI分数只用于排序/提示。
- 模型/Prompt/Skill/Workflow/数据分布变化后重新评测；线上异常触发L1/L0回退。

## 7. 可观察性与审计

所有请求、WorkItem、AgentSession、ExecutionTask和外部SyncAttempt使用traceId/correlationId关联。至少采集：

- 结构化日志、指标和分布式Trace；
- Agent/Skill/Prompt/Workflow精确版本、工具调用、输入输出摘要和verdict；
- 授权ALLOW/DENY、ReviewDecision、版本发布、Secret使用和外部回执；
- 数据质量、队列、Runner、成本、错误预算和降级告警。

告警阈值必须基于基线和错误预算批准。跨租户访问、humanOnly越权、Secret外泄和审计链中断始终为安全高优先级事件。

## 8. 可维护性与兼容

- 外部契约由OpenAPI和事件契约驱动；operationId唯一，Schema引用可解析。
- API兼容代际与产品版本分离；破坏性变更遵循32/37号迁移规则。
- 数据库通过Alembic迁移、空库升级、重跑、降级/恢复和RLS测试验收。
- 代码目标：类型检查、lint、单元/契约/集成/E2E分层；覆盖率只作为风险信号，不设脱离代码类型的统一百分比。
- 文档变更同步术语/领域/API/DB/PRD/治理并追加CHANGELOG。

## 9. 无障碍与可用性

- 核心任务、审核、Diff、结果和错误流程支持键盘操作、语义化标签、焦点管理和非颜色提示。
- 对AI结论展示证据、限制、版本、可修改内容和人工责任，不使用误导性的“AI已批准”。
- 长任务显示阶段、预计/已用时间、取消、降级和恢复条件。
- V1以WCAG 2.2 AA检查清单和真实用户任务测试建立基线。

## 10. Given/When/Then门禁示例

### AC-01 跨租户失败关闭

- **Given** 请求上下文Tenant与目标资源不一致；
- **When** 服务/API/DB访问发生；
- **Then** 各层拒绝且不泄漏资源存在性，AuditLog记录脱敏事件。

### AC-02 AI依赖不可用

- **Given** LLM持续超时且备用策略不可用；
- **When** L2 Workflow执行；
- **Then** 停止自动节点、保留草稿/Trace、WorkItem阻塞或回退L0/L1，不发布正式资产。

### AC-03 幂等冲突

- **Given** 同一Idempotency-Key已经绑定payload A；
- **When** 客户端提交payload B；
- **Then** 返回`IDEMPOTENCY_CONFLICT`且不产生第二个业务副作用。

### AC-04 指标不可伪造

- **Given** 版本计划提出延迟或效率目标但无基线/工作负载；
- **When** 进入交付评审；
- **Then** 该目标标记不可验收，不得用于宣称版本达标。
