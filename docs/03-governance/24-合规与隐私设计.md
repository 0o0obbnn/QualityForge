# 24-合规与隐私设计（V1 试点基线）

> 状态：现行权威源（合规与隐私域）· 立项 2026-08-18（CHANGELOG 批次四十二，OPN-04 关闭）
> 范围：V1 试点（本地单租户运行时，deterministic-local Provider，零外部出站）
> 裁决依据：台账裁决（CHANGELOG 批次三十三）——合规五缺口不阻塞 V1；**LLM 出站审批与保留期限须在 V1 接真实模型前关闭**，指标数据字典先于报告签署验收落地；40 号产品全面评估报告 D.1.5/D.3。

|---|---|---|---|

### 0.2 与 C2 裁决的关系

C2（V1 不接真实 LLM）意味着当前运行时零外部出站：生成链路由 deterministic-local Provider 承载，无任何用户内容离开本机。因此 §3 出站审批是**接真实模型的前置设计**而非对现存缺陷的补救；§2 保留期限自 V1 试点起生效（审计/证据台账已在产出）。

### 0.3 验收豁免清单（V1 不承诺项）

- 到期自动清理的代码实装（归接真实模型批次，本批只定数字与策略）
- 数据导出专用 operation（经既有只读 API 自取，专用 op 延后 V2）
- 多租户角色权限矩阵（V1 单租户本地全量授予）
- 数据驻留的多区域策略（V1 本地单区部署）

以上均为数字/流程之外的工程实装，与 O3「先基线后批准」裁决同构，不产生新的功能承诺。

## 1. GDPR 与数据主体权利

### 1.1 现状

- V1 为本地单区部署（SQLite 本地运行时），数据处理全部发生在用户本机；无跨境传输、无第三方数据接收方（deterministic-local 无出站）。
- 审计不可篡改已有两处哈希链载体：`execution_evidence`（M3）与 `domain_events`（批次四十一，prev_digest 串链 + 启动/查询前 fail-closed 校验，篡改返回 409 EVENT_CHAIN_TAMPERED）。

### 1.2 数据驻留策略

- V1：数据仅存于部署实例本机 SQLite 文件（`SQLITE_PATH`），不出境、不出机。
- 接真实模型后：出站内容受 §3 双闸门约束；数据驻留区域承诺随部署拓扑批准（20 号 §3 RTO/RPO 同口径，拓扑明确后批准）。

### 1.3 被遗忘权（删除权）流程

租户注销时的彻底删除流程（定义即口径，实装归接真实模型批次）：

1. 触发：租户所有者发起注销（人工确认 + 口令复核，与认证卫生同口径）。
2. 清理范围：SQLite 全部业务表与台账表——工作区/工作项/产出物版本/审核任务/会话/执行链、`execution_evidence`、`domain_events`、`provider_call_records`、`defect_sync_attempts`、认证凭据（口令哈希与令牌）。清理模式复用既有 `clear_workflow` 全表清理实现。
3. 派生物：失败聚类、知识条目等派生数据随源表同批清理，不留匿名副本（V1 无独立向量库）。
4. 备份：V1 无自动备份；如用户自行备份，备份副本随 §2 保留期限自然过期，不另行追删。
5. 留痕：注销动作本身记一条审计事实（注销时间与操作者，不含被删内容），满足「删除可证明」而不违反被遗忘。

### 1.4 导出权与访问权

- V1 口径：数据主体（即本地用户）经既有只读 API 自取全部自身数据（list 系列 operation + Observability 双面），无导出专用 op；专用导出 operation（打包/机器可读格式）延后 V2，列入延期口径说明。
- 访问权：所有读面 operation 均经 workspaceId 403 门控，无跨工作区越权读取面（既有测试覆盖）。

## 2. 数据保留期限数字（强制项）

> 以下数字为**策略设计值**，自 V1 试点起生效，试点运行后按实际数据量与审计需要校准；数字属保留策略而非指标基线，不产生 AC-04 意义上的目标值承诺。

### 2.1 逐台账保留期限

| 台账/数据类 | 载体表 | 保留期限 | 口径说明 |
|---|---|---:|---|
| 领域事件流 | `domain_events` | 365 天 | append-only 哈希链；D3/D4 指标计算窗口为 FULL_HISTORY，超期事件归档前完成窗口聚合 |
| 执行证据 | `execution_evidence` | 180 天 | 版本门禁六类证据引用期内须可复跑；门禁证据包归档文件不受此限（文档层长期保存） |
| Provider 调用台账 | `provider_call_records` | 365 天 | AI 类证据审计与成本追溯需要；PROVIDER_SWITCH 记录同期 |
| 外部同步回执 | `defect_sync_attempts` | 365 天 | B2-4 批准+回执链审计 |
| 业务数据（工作项/产出物/用例/缺陷等） | 各集合表 | 随租户存续 | 不设期限；租户注销即删（§1.3） |
| 认证凭据 | 认证表 | 随账户存续 | 注销即删；口令哈希 scrypt 参数 N=2^14 |

### 2.2 到期清理策略（实装延后声明）

- 清理单元：按 occurred_at/created_at 时间戳逐行删除，超期行删除前不破坏哈希链完整性——domain_events 采用「链头重锚」方式（删除段前缘事件的 prev_digest 重设为新 GENESIS 锚并记录重锚事件），具体实装设计归接真实模型批次（契约先行）。
- V1 试点期数据量远低于期限容量，不清理不影响运行；本节数字作为接真实模型批次的验收输入。

## 3. LLM 出站审批（强制项）

### 3.1 现状口径

V1 使用 deterministic-local Provider，**零外部出站**，无需出站审批——此口径显式声明，避免把「无审批」误读为「审批缺失」。

### 3.2 切换真实 Provider 双闸门（接真实模型前置条件）

任何从 deterministic-local 切换到真实 LLM Provider 的动作必须顺序通过两道闸门，任一不通过即维持 deterministic-local（Plan B，M5 既有语义）：

1. **闸门一：黄金集评估闸门（已实现，M5）**——候选 Provider 四步回放结构判分 + 2 条负例零容忍（false-accept=0），不达标 422 PROVIDER_GATE_REJECTED。
2. **闸门二：出站审批记录（本批定义，接真实模型批次实装）**——切换请求须附出站审批记录，字段：审批人（humanOnly）、审批时间、候选 Provider 标识、**出站数据类别清单**（逐类勾选，见 §3.3 白名单）、脱敏策略确认（勾选即承诺按 §3.3 执行）。记录落不可变台账（模式复用 PROVIDER_SWITCH 台账），缺失或字段不全 fail-closed 拒绝切换。

### 3.3 Prompt 脱敏与最小化出站策略

- 最小化原则：只传完成任务所必需的结构上下文与任务描述；用户上传的 PRD/需求正文默认**不整文出站**，以摘要与结构骨架替代（生成链路现有 summarize 步骤即此形态）。
- 出站数据类别白名单（逐类别审批，未勾选类别不得出站）：任务类型与工作流标识、产出物结构模板、脱敏后的需求摘要、审核意见要点。明确排除：凭据/Secret、个人身份信息、未脱敏商业数据。
- 测试需求文档常含商业敏感信息（40 号报告 D.1.5 定性），白名单外类别的出站请求在 Provider 适配层拦截并留痕。
- 私有化部署 LLM 为替代路径（不经公网出站），届时出站审批降级为部署审批，口径同 §3.2 台账留痕。

## 4. 指标数据字典

### 4.1 字典化口径

20 号 §1.1 受控 metricKey 登记表（51 项）为唯一登记源；字典三要素（分子/分母/数据源）的权威定义位置如下：

- **25 项 V1 验收基线（✅ 且已服务端实装）**：eff×6、qual×8、ai×9、trace_version_summary_completeness、ops_degrade_rate——字典即代码：`backend/src/qf/services/metrics.py` 逐项实现，运行时经 `listMetrics` 返回 numerator/denominator/basis/window 字段，前端与报告以接口返回为准，**不得在消费侧推导分母**（墙 M-137 同口径）。
- **登记表 ✅ 但未入 V1 基线的 3 项**（ops_wip、ops_throughput、ops_sla_timeout_rate）：载体齐备（工作项/执行台账），采集不断档；未列入 O3 裁决的 25 项验收基线，字典补齐与实装归后续批次，不豁免登记。
- **⚠️ 部分载体项**：V1 仅要求采集不断档 + 基线可建（O3 三档处置第 ② 档），字典给采集口径声明：eff 类依赖人工处理时间戳（试点期自然产出）、qual_false_accept_rate 离线口径（B13 裁决键名随质量表就范）、qual_coverage_effective 以五维度 effective 口径为准（M4 实装）。
- **❌ V1 无载体项**（eff_tool_switch_count、qual_repro_rate、qual_knowledge_hit_rate、ai_hallucination_rate）：验收豁免，载体延后 V2（O3 第 ③ 档），字典仅保留定义与延后声明。

### 4.2 目标值纪律

全部 51 项当前无批准目标值（22 号 §6 先基线后批准；AC-04）：目标值只以试点基线 + 压测/评审批准产生，本字典不承载任何目标值字段。
