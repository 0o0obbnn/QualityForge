# 21-AI介入点与降级治理矩阵

> 本文是AI自治等级、介入点、降级条件和人工硬门的唯一权威源。产品目标不是让AI替测试人员作最终质量判断，而是让AI承担可委派的收集、生成、执行、分析和整理工作，让测试人员集中于审核、批改、例外处理与全局质量控制。

## 1. 不可突破的产品底线

1. AI可以生成和修改草稿、执行测试、分析结果、提出Defect与报告草稿；不能批准、签署或发布自己的正式产出物。
2. TestStrategy、TestPlan、TestCase、AutomationScript、ResultAnalysis、Defect、TestReport、KnowledgeEntry均必须按ReviewPolicy经过至少一名具备能力的人类批准。
3. 外部缺陷写入、代码仓库写入、质量门禁豁免或放行、生产邻近操作、Secret访问和权限放宽必须独立授权；TenantAdmin开关不能绕过。
4. AI结论与执行事实分层。推断、置信度和建议不得覆盖ExecutionResult、Evidence、人工决定或外部系统回执。
5. 任一授权、来源、版本、摘要、校准或运行能力缺失时fail-closed；若缺口可由人工补充，同时生成可审计ClarificationRequest，不得由AI默认补齐关键事实。

## 2. 自治等级

自治等级描述AI在人工硬门之前可以连续完成多少工作，不代表正式批准权。

| 等级 | 名称 | AI可做 | 人工职责 | 适用场景 |
|---|---|---|---|---|
| L0 | 人工模式 | 不调用生成式AI；只用确定性校验或传统工具 | 完成全部业务工作 | AI不可用、政策禁用、数据不可出域 |
| L1 | 辅助模式 | 只读检索、解释、建议、单步草稿 | 每步选择与修改 | 新介入点、无校准集、高风险试点 |
| L2 | 受限代理 | 在固定Workflow、预算和权限内连续生成草稿、运行检查或测试；到硬门暂停 | 审核正式产出物与例外 | 默认产品模式 |
| L3 | 扩展代理 | 在经过评测的范围内跨多个工作项自动编排、重试和纠错；仍在正式审核/外部写入门前暂停 | 抽样过程监督、正式批准与全局控制 | 有真实基线、持续评测和回滚能力后的成熟场景 |

L3不是“无人测试”。正式产出物审核、外部写入批准、报告签署、门禁放行和权限管理在所有等级均保留人工硬门。

## 3. 默认等级与上调条件

- 新介入点默认L1。
- 已有固定输入输出契约、最小权限、可观测Trace、失败回滚和人工硬门的介入点可默认L2。
- 只有在代表性Golden Set上达到经批准的质量门槛，并完成影子运行、误放/误阻评估、成本与延迟基线后，才可上调L3。
- 管理员只能在平台允许的上限内调低或申请上调；不能把人工专属能力改成机器能力。
- 等级变更必须版本化、审批、记录AuthorizationDecision和AuditLog，并支持立即回退。

## 4. 阈值与校准治理

禁止在各PRD或代码中散落`0.80/0.85/0.90/0.92/0.95`等未经证明的“通用置信度”。每个阈值必须引用一组经批准的版本化校准记录（由EvalDataset/EvalRun结果和AI策略版本共同构成），至少包含：

| 字段 | 说明 |
|---|---|
| interventionKey | 对应本矩阵中的唯一介入点 |
| model/prompt/skill/workflowVersion | 被评测对象的精确版本 |
| datasetVersion | 代表性Golden Set版本与适用范围 |
| metricDefinition | 准确率、召回率、误放率、误阻率等计算方式 |
| threshold | 经评审批准的数值，不在PRD重复定义 |
| sampleSize/baseline | 样本量和人工基线 |
| validFrom/expiresAt | 生效和重新校准时间 |
| fallbackLevel | 未达阈值时回退的自治等级 |

没有有效校准记录时，模型分数只可作为排序或提示信息，不能自动触发资产变更、缺陷提交、质量门禁或L3执行。

## 6. 降级、熔断与恢复

### 6.1 触发规则

命中以下任一条件立即停止当前自动步骤，并按介入点回退至L1或L0：

- 输入来源、精确版本、内容摘要或授权上下文缺失/变化。
- 触达不在allowlist内的Skill、工具、文件、网络、Secret或外部系统。
- Workflow循环、超时、预算超限、重复失败或Runner能力不足。
- 产出物涉及关键路径、来源冲突、职责分离或强制人工检查点。
- 校准记录过期、评测跌破门槛或线上误放/误阻超过警戒线(N 与阈值为校准参数,试点后批准,裁决 2026-08-15 B13)。
- 模型、Prompt、Skill或Workflow版本变化但尚未重新评测。

### 6.2 运行行为

降级必须：停止未开始节点；保留已完成产物和Trace；把WorkItem置为`BLOCKED`或`PENDING_REVIEW`；记录原因码、版本和恢复条件；不得静默切换模型后继续发布。

### 6.3 恢复

恢复只能在问题修复、权限重新计算、必要人工决定完成且受影响输入重新锁定后进行。重放创建新的run/attempt并引用原失败记录，不覆盖历史证据。

## 7. 验收标准

### AC-01 正式产出物不可自动批准

- **Given** 任一AI生成了八类正式产出物的新版本；
- **When** Workflow尝试把版本直接置为`APPROVED`或`PUBLISHED`；
- **Then** 授权被拒绝并创建/保留ReviewTask，AI运行不得拥有ReviewDecision。

### AC-02 管理员不能关闭人工底线

- **Given** TenantAdmin把某介入点申请提升至L3；
- **When** 该Workflow到达外部写入、报告签署或正式产出物审核；
- **Then** 系统仍暂停等待具备相应能力且满足职责分离的人类决定。

### AC-03 无校准不得使用分数自治

- **Given** 介入点没有有效的版本化校准记录；
- **When** 模型返回高置信度；
- **Then** 分数只用于排序/提示，不得据此跳过检查、审核或外部写入批准。

### AC-04 降级证据完整

- **Given** Workflow发生越权、循环、超时或版本陈旧；
- **When** 熔断触发；
- **Then** 后续节点不启动，WorkItem、Trace、原因码、输入输出摘要和恢复条件均可审计。
