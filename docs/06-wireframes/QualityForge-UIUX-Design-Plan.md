# QualityForge UI/UX设计计划

## 1. 设计目标

让测试人员用最少切换完成“看任务→审AI产出→批改→执行→审质量结论”。界面应把复杂Agent技术退到可解释的运行详情，把产出物、证据、风险和人工责任放在主流程。

## 2. 体验原则

1. 任务优先：默认首页是任务看板而非统计Dashboard。
2. 产出物优先：策略、计划、用例、代码、分析、Defect、报告和知识使用统一版本/审核语言。
3. 事实分层：执行事实、AI推断和人工决定视觉上明确区分。
4. 审核即主流程：Diff、来源、证据、检查、风险和批改能力不藏在二级弹窗。
5. 渐进披露：业务用户先看结论/待办；Trace、Prompt、Token和工具调用进入详情。
6. 安全可见：权限不足、职责分离、陈旧版本、敏感证据和外部写入有明确阻断解释。
7. 可恢复：异步任务显示取消、降级、重试/重放和恢复条件。

## 3. 八模块导航

```text
任务看板
知识库
测试策划与设计
自动化测试开发
测试执行
质量分析与缺陷
AI Agent中心
平台管理
```

Tenant、项目（Workspace）和Release是全局上下文，不作为第9个业务模块。Skill位于AI Agent中心；APIContract位于知识库；CI/CD能力分别位于测试执行、质量分析与缺陷和平台管理。

## 4. 三条重点用户旅程

### A. 审核AI生成测试资产

待审核列表 → 打开策略/计划/用例审核包 → 查看来源与Diff → 修改/评论 → 批准、退回或拒绝 → 看板更新。目标是无需跳转多个技术页面即可完成专业判断。

### B. 审核自动化代码并执行

用例版本 → 代码草稿/绑定 → 检查结果与Diff → 人工代码Review → 建执行计划 → 实时任务/证据 → 失败分类。

### C. 从失败到Defect/报告

执行结果 → AI分析卡片（证据+限制）→ 人工修正 → Defect草稿审核 → 外部同步单次确认 → 报告范围/分母/风险签署。

## 5. 核心组件

| 组件 | 用途 |
|---|---|
| ContextSwitcher | Tenant/项目/Release切换，提示未保存内容和权限范围 |
| WorkItemCard | 状态、当前actor、阻塞、产出和下一动作 |
| ReviewPackage | 版本/摘要、Diff、SourceTrace、checks、Evidence和决定 |
| AgentRunPanel | Workflow节点、版本、耗时、成本、verdict和降级，不显示隐藏思维链 |
| EvidenceViewer | 日志、请求/响应、截图/视频、Trace，按权限脱敏 |
| StatusBadge | 正确区分草稿、待审、陈旧、失败、错误、阻塞和已批准 |
| ExternalWriteConfirm | 目标系统、操作、payload摘要、敏感字段、幂等键和批准 |

## 6. 无障碍与内容规范

- 目标WCAG 2.2 AA；所有核心流程支持键盘、焦点管理、语义标签和非颜色状态提示。
- 文案使用“AI草稿/建议/检查通过”，不使用“AI已确认正确/已批准”。
- 错误给出发生了什么、影响、证据、可执行下一步；不暴露内部异常或敏感信息。
- 百分比必须可展开查看分子、分母、排除项和时间窗口。

## 7. 设计与验证顺序

1. 先完成页面地图和三条旅程低保真流程。
2. 用真实测试任务做可用性走查，重点验证审核认知负担和跨模块切换。
3. 对任务看板、ReviewPackage、代码Review、执行证据和报告签署做高保真原型。
4. 同时执行权限/陈旧/降级/空状态/大量数据/移动窗口和无障碍测试。
5. 原型评审通过后再形成前端开发Backlog；视觉稿不反向修改领域/API权限契约。

## 8. V1验收

- 用户能从首页在三步内进入任何待办或待审核项。
- 审核人无需查看原始Agent Trace也能理解来源、变化、风险和机器检查；需要时可下钻。
- 无权限、自批、陈旧摘要和blocking check失败均有明确阻断。
- FAILED/ERROR/BLOCKED/INCONCLUSIVE不会被误解为通过。
- UI项目上下文只映射Workspace，不产生Project双实体。
