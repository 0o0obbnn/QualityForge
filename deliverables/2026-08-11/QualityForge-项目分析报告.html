一、项目是什么

QualityForge 定位为 AI-Native 智能化端到端测试平台:把 LLM 与 Agent 深度整合进测试全生命周期——需求解析、用例设计、脚本编写、自愈执行、根因诊断(RCA)、知识沉淀,形成闭环。核心理念是"AI 是无感的能力底座",所有 AI 能力都镶嵌在测试工作流中,而不是一个游离的聊天窗口。

当前没有任何应用代码:全部产出是 Markdown 设计文档 + 1 份 OpenAPI + 30 个 Skill 原型 + Gate 0 Agent 治理配置。技术栈(规划中):Python 3.12 + FastAPI + LangGraph + React 18 + PostgreSQL 16 + PGVector + Redis 7 + RabbitMQ。

二、核心业务闭环(平台工作流)

1. 创建工作空间
Workspace:项目入口与全局上下文容器,含系统信息、环境、AI 上下文;Saga 保证"空间+AI 上下文+默认环境"原子创建
2. 导入 PRD / Swagger 契约
需求文档解析,编译为结构化 TestingIR(需求项/业务规则/实体模型/状态机/接口契约/约束)
3. AI 解析需求并生成测试方案
TestDesign:场景树 → DesignTestCase 草稿 → 工程师审批 → 迁移为正式 TestCase
4. 生成资产并配置执行
TestAsset:用例、自动化脚本、Locator、Mock、测试数据
5. 分布式执行
Execution:Runner 节点池并发调度、WebSocket 实时日志流、状态机 Pending→Running→Completed/Failed/Cancelled
6. AI 根因分析与聚类
QualityIntelligence:RCA 归类 ProductBug/ScriptIssue/EnvIssue/FlakyTest,失败聚类,写 Jira 需人工确认
7. 知识沉淀闭环
KnowledgeCenter:经验 → PendingReview → 审核 → Published 向量化,支撑 RAG 越用越聪明
8. CI/CD 质量门禁
三级卡口:Warning 放行 / Blocked 拦截 / Quarantined 隔离,AI 智能测试选择(TIA)

四、架构与技术选型

纯 Python 微服务(7 个服务)

  • gateway / workspace / test-asset / settings
  • test-design / execution / intelligence / agent
  • FastAPI + SQLAlchemy 2.0 async + Pydantic v2
  • LangGraph 做 Agent DAG 编排

存储与中间件

  • PostgreSQL 16 + RLS 多租户 + PGVector
  • 知识图谱用邻接表建模,不引入 Neo4j
  • Redis 7 缓存/锁 + Redis Streams 日志总线
  • RabbitMQ 事件驱动 + Saga 分布式事务

前端

  • React 18 + TypeScript + Vite
  • Zustand 状态管理 · Radix UI
  • Vanilla CSS + CSS Modules(禁 Tailwind)

LLM 网关降级链

  • 主通道 → 备用通道 → 备用通道 → 本地规则(L3)
  • 置信度不达标视为失败继续降级
  • 无兜底规则的介入点显式转人工
  • 阈值由 21 号矩阵单一事实源提供

五、AI 治理:介入点降级矩阵(核心设计)

全平台每个 AI 介入点都有 L1(全自动)/L2(AI+人工确认)/L3(纯人工)三级降级策略,遵循"默认安全、可选激进":默认级别由"动作可逆性 × 影响范围"决定。绝大多数介入点默认 L2,只有只读/可逆且高阈值兜底的动作为 L1。

介入点默认级别阈值关键依据
Locator 自愈L10.92可逆 + 失败回退
运行期异常检测L10.85只读观测
Multi-Agent 编排L10.85可中断、只写草稿
需求分析与用例生成L20.80写草稿库,人工终审
覆盖率补齐L20.90禁止静默合成入库
用例优化重构L20.88改动既有资产须 diff
RCA 与缺陷提交L20.85写外部系统(Jira)
发布风险预测/门禁L20.80控制发布闸门,最高危
Skill 生成与发布L2100% 校验RCE 攻击面
CI/CD 智能选择与门禁L20.90同发布闸门

六、Gate 0:Agent/Skill 运行治理(机器可读)

当前落地的最小治理模型:1 个监督者 + 3 个受限 Subagent + 13 个 Gate 0 核心 Skill,配置在 prototypes/agent-governance/ 下,可被机器验证(validate.py)。

Agent职责Skill allowlist关键禁止
qf-supervisor分类、预检、派发、终止、汇总plan-orchestrator不生成业务资产、不审批
qf-requirement-ir需求评审包 + TestingIR 草稿requirement-quality-gate / business-rule-extractor / domain-model-extractor / state-machine-builder / requirement-compiler不改原始需求、不批准自己产出
qf-test-design策略/场景/用例/断言草稿strategy-planner / scenario-generator / test-case-generator / assertion-generator不执行测试、不改已验证 IR
qf-independent-verifier独立验证 + 人工路由ir-validator / assertion-verifier / coverage-analyzer / hitl-gatekeeper不修复被审资产、不代替人工批准

核心原则:生成者与验证者分离;Subagent 只读权威资料、只写单次运行目录、默认零网络零 Secret;任何 AI 无权批准自己的结果、写正式资产或控制发布门禁。工作流 DAG 覆盖 需求质量 → 业务规则/领域模型/状态机 → 编译 IR → 验证 IR → 策略 → 场景 → 用例 → 断言 → Coverage → HITL,遇到 REJECT/ERROR/TIMEOUT 即停止并保留证据。

十、下一步建议(项目自身已指明)

项目资料已经具备继续工作的基础,下一份有效产物不应是新的平台总纲,而应是:

"测试用例设计生成验证功能"的范围与技术 Spike 决策包: 1. 脱敏真实需求样本 2. 字段/跨字段/状态/数据质量/破坏性规则金标 3. 第一版必须做/不做清单 4. AI、确定性规则、人工的责任边界 5. 五个技术 Spike 及通过标准 6. 模块化单体技术基线候选 7. 人工 vs AI+人工 对照测量方案 8. Go / Revise / Stop 条件
