# QualityForge 用户故事集

> 编制日期：2026-08-15
> 依据权威源：`docs/01-product/01-产品功能地图v2.0.md`、`02-PRD总纲.md`、`docs/02-prd/10-17 号模块PRD`、`docs/00-navigation/54-项目需求资料总索引.md`
> 范围说明：故事以 V1（单 Workspace 试点闭环）为主，标注 `[V2]`/`[V3]` 的为后续阶段增强项。
> 验收标准采用 Given/When/Then，覆盖正常、异常、权限与降级路径（PRD 总纲 §8）。

## 角色速查

| 角色 | 核心目标 |
|---|---|
| TestEngineer | 高效完成日常测试交付：批改用例/代码、触发执行、分析和处理 Defect |
| TestLead | 控制范围、风险和交付质量：审核策略/计划/报告、裁决关键例外 |
| WorkspaceAdmin | 维护 Workspace 运行条件：成员、环境、集成引用和一般配置 |
| TenantAdmin | 治理租户资源和策略：成员、配额、共享集成、角色委派 |
| PlatformAdmin | 维护平台基础设施：租户生命周期、安全运维 |
| ViewerAuditor | 只读查看授权范围的审核链和执行证据 |

注：Approver 不是固定全局角色，而是 ReviewTask 中由 ReviewPolicy、能力、作用域和职责分离计算出的临时职责。

## Epic A · 从需求到可审核测试资产（Journey A）

### 模块：知识库（11 号 PRD）

**US-A1 · 导入测试依据来源**（V1）
作为 TestEngineer，我想要导入 Markdown/OpenAPI 文件作为来源并固化为不可变 SourceSnapshot，以便后续所有测试产出物都能引用有版本、有摘要的精确依据。
- Given 我上传一份需求文档；When 导入完成；Then 系统生成不可变 SourceSnapshot，记录原文、定位、摘要和时间。
- Given 同一来源重新抓取；When 内容变化；Then 产生新快照，不覆盖旧快照。
- Given 文档破损或格式不支持；When 解析失败；Then 保留导入失败记录并转人工补录，不编造解析内容。

**US-A2 · 需求文档版本化**（V1）
作为 TestEngineer，我想要 RequirementDocument 以稳定根 + 不可变版本管理并保留 SourceTrace，以便规则歧义可回溯到原文位置。
- Given AI 从需求文档提取 BusinessRule；When 我查看该规则；Then 可定位 SourceSnapshot、文档版本和原文位置，摘要与原文一致。

**US-A3 · API 契约管理与冲突处理**（V1）
作为 TestLead，我想要 APIContract 有唯一 Owner、版本化管理，且 DECLARED 与 OBSERVED 证据并存，以便契约漂移不会被静默覆盖。
- Given OpenAPI 声明某字段必填但流量观测中缺失；When 导入 Observation；Then 两类证据并存并创建冲突 WorkItem，不自动修改已批准 APIContractVersion。
- Given 我为 Release 批准了 APIContractBaseline；When 契约出现新版本；Then 原执行仍能解析到旧版本及摘要，新版本不自动替换历史基线。

**US-A4 · 知识条目人工发布**（V1）
作为 TestLead，我想要 KnowledgeEntry 草稿必须经至少一名人类批准才能发布，以便已审核知识不被 AI 污染。
- Given AI 从失败历史生成 Pattern 草稿；When 生成完成；Then 状态为 PENDING_REVIEW 且 ReviewTask 绑定版本/摘要，Agent 不能发布。

**US-A5 · 带来源的检索**（V1）
作为 TestEngineer，我想要检索结果附带 sourceTrace、version、digest 和适用范围，以便我判断命中内容是否可信。
- Given 检索返回高相似度条目；When AI 引用该条目；Then 不得把高相似度当事实，用户可排除错误来源。
- `[V2]` 作为 TestEngineer，我想要关键词/向量/图谱混合检索，以便更精准地组装上下文。

### 模块：测试策划与设计（12 号 PRD）

**US-A6 · AI 生成测试策略草稿**（V1）
作为 TestEngineer，我想要 AI 基于已固化来源和契约基线生成风险驱动的 TestStrategy 草稿并通过结构检查，以便我集中精力审核范围、风险和方法。
- Given Release 已存在 TestStrategy；When 我安排里程碑和资源；Then 创建 TestPlanVersion，不修改策略，也不创建 Runner 执行配置（策略/计划/执行计划三者分离）。
- Given 来源质量差或规则冲突；When 生成受阻；Then 创建 BLOCK_HUMAN（创建 ReviewTask 并暂停），不静默降级输出。

**US-A7 · AI 生成测试计划草稿**（V1）
作为 TestLead，我想要 AI 生成含阶段 DAG、里程碑、资源和验收准则的 TestPlan 草稿，以便我审核资源、时间和依赖后批准。
- Given 策略未批准；When AI 生成计划；Then 计划可生成草稿但不能批准或启动执行。

**US-A8 · AI 生成用例草稿且不可直接入库**（V1）
作为 TestEngineer，我想要 AI 生成正向、反向、边界、权限、异常场景的 DesignTestCase 草稿，并在独立验证和覆盖分析后进入人工审核，以便业务正确性由人把关。
- Given AI 生成高置信度 DesignTestCase 且所有机器检查 PASS；When 提交；Then 仍创建 ReviewTask，人工批准后才生成/发布 TestCaseVersion。
- Given 我退回用例 V1 并给出意见；When Agent 按意见修改；Then 创建 V2 并重新检查/审核，V1、决定和 Trace 保持可查。

**US-A9 · 覆盖分析分母透明**（V1）
作为 TestLead，我想要设计覆盖分析展示分子、分母、排除项、未覆盖项和每条 SourceTrace，以便我不会被"生成数量"冒充的覆盖率误导。
- Given 覆盖分析声称 90%；When 我查看详情；Then 可见分子、分母、排除项、未覆盖项和 SourceTrace。
- Given 覆盖映射不足；When 生成完成；Then 标记 INCONCLUSIVE 或缺口，不自动补齐后静默发布。

**US-A10 · 陈旧版本重评**（V1）
作为 TestEngineer，我想要来源/契约版本变化时受影响的草稿和已批准版本被标记待重评，以便旧批准不会静默覆盖新内容。
- Given 已批准用例引用 APIContractVersion V1；When Release 基线切换 V2 且存在 breaking change；Then 用例进入受影响队列，旧批准不自动覆盖 V2。

### 模块：任务看板（10 号 PRD）

**US-A11 · 统一工作入口**（V1）
作为 TestEngineer，我想要在看板查看分配给我的任务、AI 运行进度、退回修改和阻塞，以便一处看清当前全部工作。
- Given AI 完成 TestPlanVersion 草稿；When Workflow 提交结果；Then WorkItem 进入 PENDING_REVIEW 并创建绑定精确版本与摘要的 ReviewTask，不直接批准。

**US-A12 · 统一审核队列**（V1）
作为承担 Approver 职责的用户，我想要按产出物、风险、Release、到期时间和职责筛选待审核队列并查看 Diff、证据和检查结果，以便高效作出批准/退回/拒绝决定。
- Given ReviewDecision 为 APPROVE/REQUEST_CHANGES/REJECT；When 提交决定；Then 决定只追加且仅 UserIdentity 可作出，Agent 不可代办。
- Given 审核人无能力/作用域或违反职责分离；When 尝试决定；Then 决定被拒绝并重新分派。

**US-A13 · AI 运行透明**（V1）
作为 TestLead，我想要看到每个 AI 运行的 Agent、Skill、版本、步骤、耗时、成本、Trace 和降级状态并可暂停/取消，以便 AI 行为可观察可干预。

**US-A14 · 阻塞管理**（V1）
作为 TestEngineer，我想要阻塞项记录原因码、详情、恢复条件和依赖，以便我判断接受风险、补资料还是调整计划。
- Given Agent 请求未在 allowlist 的外部写入；When 节点执行前授权；Then 调用不发生，WorkItem 阻塞并记录 DENY 原因。

**US-A15 · 看板统计**（V1）
作为 TestLead，我想要查看 WIP、周期时间、审核时长、阻塞时长、AI 成功率与成本等指标，以便持续改进流程（指标不作个人绩效自动裁决）。

## Epic B · 从正式用例到自动化结果（Journey B）

### 模块：自动化测试开发（13 号 PRD）

**US-B1 · AI 生成自动化脚本**（V1 MUST）
作为 TestEngineer，我想要基于已批准的 TestCaseVersion / APIContractBaseline 让 AI 生成 Web/API AutomationScriptVersion 草稿，以便代码草稿带着依赖锁、运行时指纹和变更摘要进入 Code Review。
- Given 脚本准备批准；When 缺 frameworkVersion、runtimeVersion 或 dependencyDigest；Then blocking check 失败，不能发布或进入执行计划。
- Given 所有静态检查 PASS；When 提交批准；Then 检查 PASS 不替代人工代码批准。

**US-B2 · 脚本与用例多对多绑定**（V1 MUST）
作为 TestEngineer，我想要一个脚本版本绑定多个精确 TestCaseVersion 并分别标注 coverageType，以便共享 setup 脚本无需复制多份。
- Given 一段登录 setup 服务于 10 个用例；When 创建脚本版本；Then 可绑定 10 个精确 TestCaseVersion，无需复制脚本。

**US-B3 · 隔离试运行**（V1 MUST）
作为 TestLead，我想要受控试跑在非 root、只读工作目录、默认零外网、超时上限和产出白名单的沙箱中运行，以便试运行不产生不可控副作用。
- Given AI 生成删除类 API 测试；When 目标环境或清理策略未授权；Then 代码可保持草稿，但试跑/执行被拒绝并说明条件。

**US-B4 · Locator 自愈不污染正式资产**（SHOULD）
作为 TestEngineer，我想要运行中 AI 发现的新 Locator 只作为带证据的候选进入 ReviewTask，以便正式 LocatorVersion 不被静默改写。
- Given 运行中 AI 找到新 Locator 并重试成功；When 运行结束；Then 原 LocatorVersion 不变，新候选带证据进入 ReviewTask。

**US-B5 · Git 模式证据链**（SHOULD，V1 末/V2）
作为 TestEngineer，我想要 Git 模式的脚本记录固定 repo、完整 commit SHA、path 和 blob SHA，以便代码资产可复现可审计；仓库写入需另行人工批准。

### 模块：测试执行（14 号 PRD）

**US-B6 · 冻结资产的执行计划**（V1）
作为 TestLead，我想要创建 ExecutionPlanVersion 时冻结 TestCaseVersion、AutomationScriptVersion、执行契约基线、Environment 和全部引用摘要，以便每次执行可复现。
- Given ExecutionPlanVersion 已创建；When TestCase 或 Script 发布新版本；Then 本次执行仍使用已冻结旧版本，新版本需新 ExecutionPlanVersion。
- Given 版本摘要不匹配；When 启动执行；Then 返回 STALE_ARTIFACT_VERSION 并禁止执行。

**US-B7 · 触发与重跑**（V1：手工、计划触发；`[V2]` Webhook/Pipeline）
作为 TestEngineer，我想要幂等地触发执行批次并在失败时受控重跑（V1 默认一次受控重试），以便结果可信且不覆盖历史。
- Given Task attempt1 失败；When 自动重试成功；Then attempt1 和 attempt2 均可查，汇总说明采用规则。

**US-B8 · 结果事实与结论分离**（V1）
作为 ViewerAuditor，我想要 ExecutionResult 只追加且 FAILED（断言不满足）与 ERROR（未形成有效验证）严格区分，以便报告不把环境失败冒充业务失败。
- Given 一个断言失败、另一个 Runner 启动失败；When 汇总结果；Then 前者 FAILED、后者 ERROR，报告不将 ERROR 计入有效业务分母而不披露。
- Given 人工添加注释；When 保存；Then 注释不能修改原始执行事实。

**US-B9 · 契约检查四态**（V1）
作为 TestLead，我想要 ContractCheckResult 按 MATCH/DEVIATION/NOT_CHECKED/INCONCLUSIVE 四态记录，以便未检查的接口不被计为契约一致。

**US-B10 · 实时观察执行**（V1）
作为 TestEngineer，我想要通过实时事件流查看 ExecutionTask 进度、日志和制品并支持断线按 offset 补拉，以便无需轮询即可跟踪执行。
- Given 我无目标 Task 访问权；When 申请 WebSocket 票据；Then 签发被拒绝且不泄漏任务存在性。
- 实时流不承载批准/修改命令。

**US-B11 · 手工测试记录**（V1）
作为 TestEngineer，我想要在看板记录手工测试的步骤结果、实际结果和证据，以便手工与自动化结果统一进入后续分析。

## Epic C · 从失败到质量交付（Journey C）

### 模块：质量分析与缺陷（15 号 PRD）

**US-C1 · AI 失败聚类与 RCA 草稿**（V1）
作为 TestEngineer，我想要 AI 基于执行事实聚类失败并生成 ResultAnalysis 草稿（含置信限制、替代解释和建议），以便我审核分析是否成立而不是从零分析。
- Given AI 聚类出 10 个相似失败；When 聚类完成；Then 只产生 FailureCluster/分析草稿，不自动创建已批准 Defect 或外部 Issue。
- Given 证据不足或关联 ID 缺失；When 分析生成；Then 标记 INCONCLUSIVE 并请求补证，不制造确定根因。
- Given 人工证据否定 AI 根因；When 审核退回；Then 新分析版本保留替代解释，原 AI 版本/证据仍可审计，ExecutionResult 不变。

**US-C2 · Defect 草稿与人工批准**（V1）
作为 TestEngineer，我想要 AI 生成含复现步骤、严重度建议和 Evidence 的 Defect 草稿并去重，以便我批准版本、流转和关闭。
- Given Defect 关闭/验证；When 提交；Then 必须附带证据。

**US-C3 · 外部同步逐次批准**（V1：手工同步也留痕；`[V2]` 增强自动同步）
作为 TestLead，我想要每次对外部缺陷系统的 CREATE/UPDATE/COMMENT/TRANSITION 写入都单独走批准并绑定幂等键和回执，以便外部状态变更始终可审计。
- Given Defect 创建同步已批准；When 后续要改变外部状态；Then 新建独立 SyncAttempt 并重新审核，旧批准不能复用。
- Given 外部系统超时；When 重试；Then 使用同一幂等键并如实记录回执，不假报成功。

**US-C4 · 测试报告签署**（V1）
作为 TestLead，我想要 TestReport 固定 scopeSnapshot 和 executionSnapshot、披露 ERROR/阻塞/排除项和契约检查摘要，并在签署后不可变，以便我对交付质量结论负责。
- Given 报告展示通过率；When 存在 ERROR/BLOCKED/SKIPPED；Then 报告显示完整分类、分母定义和排除理由，不把无效执行算 PASS。
- Given 签署后数据快照变化；When 需更正；Then 产生新版本，不改写已签署内容。

**US-C5 · 执行覆盖率报告**（V1）
作为 TestLead，我想要按批准的分母口径与快照生成 CoverageReport（已检查/偏差/未检查/不可判定），以便覆盖率结论可复算。

**US-C6 · 质量门禁**（`[V2]`）
作为 TestLead，我想要执行版本化的确定性门禁规则，放行/阻断豁免由人决定，以便 AI 建议不能自动放行或阻断发布。

## Epic D · AI 可控、可审计、可降级（AI Agent 中心，16 号 PRD）

**US-D1 · Skill/Agent/Workflow 分治**（V1）
作为治理人员（TenantAdmin/平台治理），我想要 Skill（原子能力）、Agent（职责/权限边界）、Workflow（版本化 DAG）分别版本化管理，以便 AI 能力边界清晰不混同。
- Given coverage-analyzer 是 Skill；When Workflow 调用它；Then 由授权 Agent 执行并分别记录 AgentVersion 与 SkillVersion。

**US-D2 · 权限取交集 fail-closed**（V1）
作为 WorkspaceAdmin，我想要 Agent 最终权限 = 发起人 RBAC ∩ AgentVersion 权限 ∩ Workflow 节点权限 ∩ 环境/集成策略 − 显式 Deny − humanOnly，以便任何一层缺失即拒绝。
- Given 用户有外部写权限但 AgentVersion 禁止；When Agent 尝试同步 Defect；Then 操作被拒绝并记录 DENY，不因用户权限放行。

**US-D3 · 机器 PASS 不等于人工批准**（V1）
作为 TestLead，我想要所有 Gate 0 checker 通过后仍创建绑定版本摘要的 ReviewTask 并 BLOCK_HUMAN，以便正式产出物批准永远由人作出。

**US-D4 · 三层证据分列展示**（V1）
作为审核人，我想要审核界面区分展示确定性检查证据、独立 verifier 裁决和人工审核决定，以便三层证据不合并、不互相替代。
- Given verifier 裁决 FAIL；When 生成独立验证结果；Then WorkItem 转 REWORK 且裁决证据只追加。
- Given verifier 超时（上限 60s）；When 按 ERROR 处理；Then 不产出裁决、不阻断人工审核，记录 ERROR 并告警。

**US-D5 · Session/Trace 全量留痕**（V1）
作为 ViewerAuditor，我想要每个 AgentSession 记录发起人、WorkItem、版本快照、授权决定、节点/tool 调用、输入输出摘要和成本（敏感字段脱敏），以便 AI 行为可审计。
- Trace 缺失或 checker 异常时，不得给 PASS，不得进入"可批准"状态。

**US-D6 · Eval 校准与降级**（V1 校准记录即承担自治判定底座）
作为治理人员，我想要用版本化 Golden Set 运行 Eval 并形成校准记录，以便没有有效校准记录时分数只排序、不驱动高价值自治。
- Given Agent 变更 Prompt；When 查看准入结果；Then 旧 Eval 只关联旧 PromptVersion，新版本必须重新运行指定 DatasetVersion。
- Given 评测跌破门槛或误放/误阻超警戒线；When 触发降级；Then 按 21 号降级矩阵回退并重建校准。

**US-D7 · 运行控制与人工接管**（V1）
作为 TestEngineer，我想要随时暂停/取消 AI 运行，并在循环、超时、预算超限时自动停止后续节点保存现场，以便 AI 不失控。

**US-D8 · 独立平台评审 Agent 隔离**（V1）
作为 TenantAdmin，我想要 qf-platform-reviewer 独立于生产委派图、只能基于冻结快照输出咨询性 Finding，以便建立对平台本身的第二视角。
- Given 生产 Agent 请求调用平台评审 Agent；When 计算委派关系；Then 请求在执行前被拒绝。
- Given 评审 Agent 发现 P1 Finding；When 它尝试整改或自行结案；Then 写入和处置均被拒绝，由人决定是否建立整改 WorkItem。

## Epic E · 平台运行条件与治理（平台管理，17 号 PRD）

**US-E1 · 项目即 Workspace**（V1）
作为 WorkspaceAdmin，我想要"新建项目"只创建 Workspace（含 Release 交付批次），以便不引入与 Workspace 重复的 Project 实体。
- Given 用户点击"新建项目"；When 保存；Then 只创建 Workspace 并返回 workspaceId。
- Given 关闭/归档 Release；When 校验；Then 先检查未完成工作和报告。

**US-E2 · 成员与 RBAC 配置**（V1）
作为 WorkspaceAdmin，我想要按 Platform → Tenant → Workspace → Resource 四级作用域配置角色绑定与显式 Deny，以便权限可委派、可收回。
- Given TenantAdmin 未获目标业务审核能力；When 尝试批准 TestReport；Then 403 拒绝并记录 AuthorizationDecision（管理员身份不自动获得业务批准）。

**US-E3 · 环境与 Secret 管理**（V1）
作为 WorkspaceAdmin，我想要 Environment 只保存 secretRef 而不存连接串明文，Secret 有 keyVersion、作用域、过期和轮换审计，以便凭据零明文暴露。
- Given 用户有环境查看权限；When 查询环境/Secret；Then 只能看到引用和元数据，响应/日志/Trace 无明文。
- Given Secret 过期或无权；When 执行需要凭证；Then 执行阻塞，不回退到明文或默认凭据。

**US-E4 · ReviewPolicy 只可调严**（V1）
作为 TenantAdmin，我想要 ReviewPolicy 定义产出物的审核阶段、人数、能力和职责分离，且平台最低要求只能调严，以便任何产出物至少保留一名人类批准。

**US-E5 · 审计只追加**（V1）
作为 ViewerAuditor，我想要 AuthorizationDecision 与 AuditLog 只追加、脱敏、可导出且访问受限，以便合规审计有不可篡改的证据。

**US-E6 · 跨租户失败关闭**（V1）
作为 PlatformAdmin，我想要请求令牌与资源 Tenant 不一致时服务层和 RLS 同时拒绝且不泄漏资源存在性，以便租户隔离 fail-closed。

**US-E7 · 紧急支持访问**（V1）
作为 PlatformAdmin，我想要 SupportAccessGrant 限时、最小能力、逐项审批、超时自动失效并全程审计，以便 break-glass 场景可控（Agent 无权发起）。

**US-E8 · 配置辅助**（V1，默认 L1）
作为 WorkspaceAdmin，我想要 AI 解释配置、预检变更并生成最小权限建议，以便降低配置错误率；AI 建议仅提示、不自动改配置，变更落审计。
