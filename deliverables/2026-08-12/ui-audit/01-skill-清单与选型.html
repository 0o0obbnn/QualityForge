二、技能选型说明

2.1 推荐组合(针对 QualityForge 27 页原型走查优化)

① 走查标准层
  • ui-ux-pro-max — 启发式检查框架
  • Craft: state-coverage(五态) + form-validation(字段校验) + accessibility-baseline(WCAG 2.2)
  • laws-of-ux — 交互组合规则
② 优化执行层
  • design-review — 逐问题原子修复
  • taste-skill — 密度/留白/对齐调参
  • ui-prototype-generator-1.0.0 — HTML 原型落地
③ 风格锚定层
  • aesthetic-preset-library → 10 Müller-Brockmann 精密网格: 数学精确网格、严格对齐、功能主义,最契合组件级走查标准
  • Craft: typography-hierarchy + anti-ai-slop

2.2 入选与排除理由

入选理由: 本项目是「既有高保真原型的细节下沉走查 + 修复」,不是从零设计。因此选「走查判据(启发式+工艺规则)+ 修复执行(design-review/taste-skill)+ 风格约束(Müller-Brockmann 网格)」的最小有效组合,避免技能堆叠。

排除理由: frontend-* / website-builder / figma-* 面向新建或 Figma 工作流,与 HTML 原型直接修复的交付形态不符;design-consultation / apple-hig 面向从零系统或移动端,项目已有 token 且为 B 端桌面;creative-director 面向概念重构,本轮不改变信息架构与视觉风格。

2.3 优化风格说明(Müller-Brockmann 精密网格)

  • 数学精确的网格: 8pt 节奏对齐(4/8/12/16/20/24/32/40/48),表单栅格、表格列、卡片间距严格归一到节奏
  • 严格对齐: 标签左对齐、数字列右对齐(mono)、按钮组右对齐、弹窗操作区统一右对齐
  • 功能主义: 无装饰元素,信息层级靠字重/字号/留白区分(与项目「呼吸感极简」兼容)
  • 禁蓝紫硬约束不变: 全体系色相避开 hue 190-320°(项目既有 token 体系)
