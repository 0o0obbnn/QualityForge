1. 这是什么

面向测试工程师、测试负责人与平台治理人员的智能测试生产线。AI Agent 承担需求解析、草稿生成、代码生成、执行、证据整理、分析与改稿；测试人员负责审核、批改、业务取舍、例外裁决和最终质量责任。平台围绕 8 类正式产出物组织功能，任何 AI 产出未经人工审核不得生效。

核心哲学（贯穿全部契约的设计不变量）

4. 核心机制

4.1 测试生命周期主闭环

来源固化→ AI 策略/计划草稿→ 人工审核→ AI 用例+代码草稿→ 人工审核/批改→ AI 编排执行·不可变结果→ AI 分析/Defect/报告草稿→ 人工审核/签署/外部写入批准→ 知识回流

4.2 Gate 0 可信数据流水线（原型已验证）

需求源→ requirement-quality-gate→ business-rule / domain-model / state-machine→ requirement-compiler→ ir-validator→ scenario-generator→ test-case-generator→ assertion-generator→ assertion-verifier→ coverage-analyzer→ GATE_PASS / GATE_FAILURE
设计不变量（校验器强制执行）：缺失证据永不变成干净 PASS（降级 PASS_WITH_REVIEW）；冲突保留全部版本；被拒断言仍留在覆盖率分母——不能靠删数据让门通过。

4.3 Agent 治理模型（Gate 0）

1 Supervisor
qf-supervisor
分类任务、验证工作流、派发、停止异常、汇总证据；无业务生成权
3 Subagent
需求IR / 测试设计 / 独立验证
各自 allowlist 技能；不能批准自己产出、不能修改权威源、不能外部写入
默认自治
L2 受限代理
零网络、零 Secret、无 humanOnly；委派深度 ≤1；最大步数 12；600s 超时

4.4 正式产出物发布事务

锁定 ReviewTask 与产出版本 → 重算授权/策略/职责分离 → 校验 contentDigest + blockingChecks → 追加 ReviewDecision/AuthorizationDecision → 推进 approved/published 指针 → 写 Outbox 事件 失败任意一步即回滚；外部写入用独立 SyncAttempt，不做分布式强一致。

7. 风险与开放项

优先级项目现状
P0运行时不存在RLS、不可变版本、人工审核、权限交集、WebSocket、幂等外部写入全是设计主张，无运行证据
P1API 成功响应过度通用94 operations 中 32 处 GenericListResponse + 41 处 GenericObjectResponse，不足以生成稳定客户端
P110 个 Skill 无标准 evals.json有 eval 脚本但缺统一契约，阻碍注册/回归/发布门禁
P1104 表实现复杂度静态完整但未证明 V1 全量物理落地必要，应靠纵向切片裁决
P2收益指标无基线已定义测量方法（效率/质量/追溯/AI效果/运营五维），但无人工基线与实测数据，禁止沿用 80%/95% 口号

① API 响应契约收敛→ ② 10 Skill eval 标准化→ ③ Gate 0 纵向切片→ ④ 最小 DB + RLS 负向测试→ ⑤ Agent 权限/审核硬门→ ⑥ Runner 与执行证据→ ⑦ 小样本度量建基线
