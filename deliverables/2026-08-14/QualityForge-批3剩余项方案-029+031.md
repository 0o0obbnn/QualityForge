## 二、031 · 多态溯源方案(应用层拦截 + 负向测试)

### 2.1 问题

t_work_item_artifact.artifact_id/artifact_version_id、t_source_trace_edge.from/to、t_review_task 的资产多态引用均无外键(33 号 L354-368/L510 等),悬空引用只能应用层拦截;DB 层无法证明"追踪链完整""审核绑定精确版本"。

### 2.2 方案(三部分)

**① 应用层引用完整性拦截(服务层统一实现)**

| 规则 | 说明 |
|---|---|
| R1 创建时校验 | 写入 artifact_id/version_id/from/to 前,按 artifactType/edgeType 查目标表存在性(同租户、同 workspace) |
| R2 删除防悬空 | 业务产出物软删除(ARCHIVED/DEPRECATED),不物理删除;硬删除仅限未引用数据 |
| R3 查询时校验 | 读取详情时校验引用存在;悬空引用返回明确错误码(REFERENCE_DANGLING)而非静默空 |
| R4 同租户约束 | 引用目标必须同 tenant_id/workspace_id(应用层断言 + 联合查询) |
| R5 幂等与并发 | 校验与写入同一事务;乐观锁(lock_version)防并发覆盖 |

**② 负向测试用例清单(随 M1 审核闭环实现)**

| 用例 | 步骤 | 期望 |
|---|---|---|
| N1 悬空 artifact | 创建 WorkItemArtifact 指向不存在的 artifactId | 拒绝 4xx + REFERENCE_DANGLING |
| N2 跨租户引用 | 引用其他 tenant 的产出物版本 | 拒绝(不泄漏存在性) |
| N3 审核绑定漂移 | ReviewTask 绑定 v1,内容更新为 v2 后批准 | 拒绝(版本一致性校验,05 §5.5.12-2) |
| N4 溯源断链 | SourceTraceEdge.from 指向已删除来源 | 查询返回断链标记,不静默 |
| N5 环依赖 | WorkItemDependency 自环/循环 | 拒绝 + 指出路径(05 §5.5.12-8) |
| N6 跨版本绑定 | TestCase 绑定已废弃用例版本 | 拒绝(STALE 语义) |

**③ 部分 FK 化评估**

| 候选 | 评估 |
|---|---|
| t_work_item_artifact.work_item_id → t_work_item | 已有 FK ✓ |
| artifact_version_id → 多态目标 | **不建 FK**(多态,DB 无法表达);应用层 R1-R4 + 定期完整性巡检任务(每日扫描悬空引用,告警) |
| t_source_trace_edge from/to | 同上,巡检任务覆盖 |
| 巡检任务 | `make audit-orphans`:扫描三类多态引用,输出悬空清单,进审计日志 |

### 2.3 落地归属

- 应用层拦截 + 负向测试:随 M1 审核闭环(ReviewTask 绑定校验)实现,N1-N6 用例进 M1 验收
- 巡检任务:随 M2 看板工作化实现(make audit-orphans)
- 不引入 DB 触发器(跨 SQLite/PG 兼容,与项目技术栈一致)

### 2.4 验收

- M1 验收:六条负向用例全 PASS
- M2 验收:audit-orphans 可运行,悬空引用报告与审计日志可见
