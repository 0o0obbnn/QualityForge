测试生命周期主闭环 — 用户视角
用户角色 × 核心页面导航 × WorkItem 状态流转

Journey A: 需求 → 测试资产

  • • 导入来源 → 固化 SourceSnapshot
  • • AI 编译 Testing IR → 生成策略/计划/用例
  • • 确定性检查 + 独立验证
  • • 测试人员在 ReviewTask 审核 Diff 与证据
  • • 批准或退回新版本

Journey B: 用例 → 自动化结果

  • • 选择已批准 TestCaseVersion
  • • AI 生成 Web/API AutomationScript
  • • 代码检查 + 人工 Code Review
  • • 创建 ExecutionPlan 冻结资产版本
  • • Runner 执行 → 只追加结果和证据

Journey C: 失败 → 质量交付

  • • AI 基于执行事实聚类 / RCA
  • • 人工审核 ResultAnalysis
  • • AI 生成 Defect 和 TestReport 草稿
  • • 人工批准 / 签署
  • • 外部写入批准 → 同步 Defect → 知识回流
