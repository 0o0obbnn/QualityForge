# 需求功能图谱

把需求资料转换为可供人和 AI 共同复核、可由测试设计 Skill 消费的证据化事实层：

```text
模块 → 功能/递归子功能 → 最小功能
                       ↘ 字段使用 → 业务字段 → 字段规则
最小功能/字段/规则 ↔ 依赖、数据流、状态流、冲突和业务流程
```

## 核心不变量

1. **证据**：已确认事实必须绑定 `source_id + locator + quote`；缺失事实保持 `inferred/unresolved`。
2. **全量**：`full` 必须建立全部相关来源单元台账并完成对账；代表性或局部结果只能声明局部范围。
3. **两遍字段**：先保留未经合并的 `field_occurrences`，再按业务对象、上下文、方向和语义归一字段。
4. **方向分离**：输入、展示、请求、响应、原值、掩码值和派生值默认独立，以字段血缘关联。
5. **最小可测**：最小功能具有单一触发、动作和可观察结果；概括标题、枚举值和页面标题不是最小功能。
6. **稳定身份**：核心 ID 基于归一化业务语义，不依赖行号、数组位置或章节编号。
7. **评审投影**：先将需求评审投影回图谱，再编译测试输入；测试生成器不同时解释原始图谱和评审报告。
8. **维度放行**：下游只消费 `READY` 维度；`REVIEW_REQUIRED/BLOCKED` 保留原因和 Finding，禁止补写假设。
9. **图谱保真**：候选、缺口和冲突留在图谱中，不通过静默删除换取 PASS。

状态组合以 [状态模型](references/state-model.md) 为唯一权威；产物类型和版本以 [Schema兼容矩阵](references/schema-compatibility.md) 为唯一权威。

## 输入与适配

- 必需：带稳定定位的 Markdown 需求资料。
- 正式建模必需：`qa-requirement-review` 产生的资料依赖评审。未提供时只能生成不可下游的发现草稿。
- 可选：接口文档、数据字典、原型说明和完整的 `qa-requirement-review` 语义评审产物。
- 默认以可定位的需求正文为权威输入。图片不经过 OCR 进入主链；仅在运行环境支持多模态且任务明确需要视觉核验时作为补充证据。
- 多来源冲突时保留双方证据和优先级，不自行选择正确版本。
- DOCX/PDF 转换或无法可靠保留表格、图片、标题时，读取并执行 [转换质量门禁](references/conversion-quality.md)。

## 按任务读取

- 开始提取或修改实体结构：读取 [提取契约](references/extraction-contract.md)。
- 执行整份需求：再读取 [全量提取协议](references/full-extraction-protocol.md)。
- 建立业务对象、规则、状态、流程和类型化边：读取 [类型化图谱契约](references/typed-graph-contract.md)。
- 明确要求核验原型图片，且当前环境支持多模态：读取 [可选视觉证据契约](references/image-review-contract.md)。
- 投影需求评审或生成下游输入：读取 [测试设计输入契约](references/test-design-input-contract.md)。
- 比较需求版本或分析影响：读取 [图谱演进契约](references/graph-evolution-contract.md)。
- 执行多阶段生成、续跑或指定阶段：读取 [流水线协议](references/pipeline-protocol.md)。
- 需求版本变化、清理陈旧实体或只复核受影响范围：读取 [增量刷新契约](references/incremental-refresh-contract.md)。

只读取当前分支需要的引用文件；契约中的字段、枚举、门禁和完成标准优先于本入口的概述。

## 执行阶段

### 1. 建立来源台账

声明 `full` 或 `representative`，逐项登记章节、表格、图片和接口。从资料依赖评审导入引用分类、可用性、Finding 和原文位置；本 Skill 只定位目标图谱实体并计算受影响范围，不重新判断项目资料是否缺失。影响范围使用最小可确认粒度：能定位最小功能时绑定 `atomic_ids`，只有原文无法继续收窄时才回退到 `function_id`，禁止将 Finding 扩散到同功能下的无关操作。完成条件：覆盖计数能由 `source_units` 重新计算，每个资料 Finding 都绑定到受影响的最小可确认范围。

### 2. 发现与归一

扫描标题、正文、列表、表格、按钮、操作列、状态说明、错误提示、接口入参和出参。先提取候选及字段出现项，再归一为模块、递归功能、最小功能、字段上下文和字段绑定。完成条件：所有实体有稳定 ID；孤立项、冲突和未解析引用进入 `gaps`。

### 3. 图谱增强

建立业务对象、字段使用、业务规则、状态、已确认业务流程和有类型关系。正文只有时序线索但无法确认完整步骤时保留为流程候选。完成条件：每条非结构关系有证据，所有边端点存在。

### 4. 语义评审与投影

需求质量结论由 `qa-requirement-review` 提供。将评审按最小功能和测试维度投影，不把一个 Finding 扩散到未受影响维度；独立非功能要求以 `non_functional_requirements` 投影，禁止伪造功能或最小功能 ID。包级评审未完成时仍继续编译已确认的 `READY` 切片，不等待所有 Finding 关闭。可选视觉证据只补充正文事实，不成为默认评审前置条件。完成条件：每个适用维度是 `READY/REVIEW_REQUIRED/BLOCKED` 之一，并保留原因与 Finding ID。

### 5. 校验与交付

运行对应结构校验器，修复结构错误；证据无法核验时降级事实状态。生成共享同一 JSON 快照的 HTML，并按最小功能编译测试设计切片。正式交给测试用例 Skill 的文件默认只包含至少一个 `READY` 维度的条目；完整图谱另行保留待确认内容。完成条件：脚本退出码为0、结构诊断为空、HTML快照一致；整体是否可下游消费按状态模型判断，不能由退出码替代。

优先使用 `scripts/run_pipeline.py` 执行主链；单阶段调试时从对应脚本 `--help` 获取参数。命令只在流水线协议或脚本中维护，不在入口重复抄写。

## 标准输出

- `<文档名>_功能点图谱.json`：权威事实层。
- `<文档名>_功能点图谱.html`：自包含交互视图。
- `<文档名>_已评审图谱.json`：需求评审投影后的版本化图谱。
- `<文档名>_测试设计输入.json`：只暴露可追溯的功能项、独立非功能项和分维度门禁。
- `<文档名>_变更影响.json`：需要比较版本时生成。

正式交付必须报告：实际输入、提取模式、来源覆盖、实体计数、未解决缺口、各维度门禁分布、校验命令及退出码。结构通过、局部 READY 或 HTML 可打开都不等于整份需求业务验收完成。

## 职责边界

本 Skill 负责需求事实提取、图谱化、评审投影和测试输入编译。完整性、明确性、可测试性、可行性和正式评审结论由需求评审 Skill 负责；测试场景和测试用例由下游测试设计 Skill 负责。
