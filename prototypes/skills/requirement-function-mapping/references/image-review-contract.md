# 可选视觉证据契约

需求正文是默认权威输入。原型图只在任务明确要求视觉核验且当前运行环境支持多模态时使用；不支持时跳过普通原型图，并对“规则见图、字段见原型”等图片唯一来源仅阻塞其所属范围。

## 输入边界

- 直接观察原始图片，不以 OCR 转写作为业务事实来源。
- 先完成正文图谱，再判断图片是否提供正文之外的信息。
- 图片中的示例数据、占位符、页面标题和布局文字不自动成为业务字段或规则。
- 视觉观察必须绑定图片 `source_id + locator`，并说明所属功能和观察区域。

## 三种结果

1. `CONFIRMS_TEXT`：图片与正文事实及上下文一致。只追加视觉证据，不新增实体。
2. `SUPPLEMENTS_TEXT`：图片补充正文未明确的字段、状态或交互。保留为 `review_required` 候选，不直接进入测试设计输入。
3. `CONFLICTS_WITH_TEXT`：图片与正文不一致。同时保留两边证据并登记冲突；正文继续作为临时测试基线，除非正式评审另有结论。

同名内容只有在业务对象、所属功能、页面区域和输入输出方向一致时才可判为 `CONFIRMS_TEXT`。无法确认上下文时使用 `SUPPLEMENTS_TEXT`，不合并实体。

## 完成标准

- 未启用视觉核验时，图片台账为 `relevant=false / skipped`，正文流程可以独立完成。
- 图片是需求唯一来源但运行环境不支持多模态时，仅相应功能或测试维度为 `unavailable/BLOCKED`。
- 每条视觉观察都能回到原图位置，不包含只来自 OCR 的文本。
- 一致内容不增加实体数量；补充内容保持待评审；冲突内容不覆盖正文。
