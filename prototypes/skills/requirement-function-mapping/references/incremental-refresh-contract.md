# 增量刷新与失效契约

增量的目标是减少需要 AI 或人工重新判断的语义范围，不以减少本地确定性扫描为首要目标。

## 策略

1. 对当前 Markdown 重新执行无模型、确定性的全文发现、归一和类型化。
2. 以新图谱作为当前需求事实全集；旧图谱中已删除来源支持的实体自然消失，不做旧新JSON局部拼接。
3. 使用稳定语义ID比较新旧图谱，沿有类型关系计算有限深度影响。
4. 只让变化和受影响的最小功能、规则、需求评审及测试用例重新评审或重测。
5. 未受影响测试用例索引可保留；指向已删除目标的 `verifies` 边删除，但旧图仍用于把删除影响传播到用例。

来源单元以 `semantic_key` 跨版本对齐，以 `content_sha256` 判断内容变化；行号只用于证据定位。旧产物缺少这两个字段时，失效模式必须是 `FULL_REVIEW_REQUIRED_LEGACY_LEDGER`，不得伪造精确的来源单元变化范围。

这种方式避免局部文本拼接产生的行号漂移、跨模块关系丢失、旧字段残留和不完整来源台账。确定性全文扫描不是“全量语义重做”。

## 执行

```bash
python3 scripts/incremental_refresh.py \
  --before-graph <旧Schema1.4图谱.json> \
  --source <新需求.md> \
  --source-review <更新后的资料依赖评审.json> \
  --review <更新后的六维需求评审.json> \
  --out-dir <输出目录>
```

正式更新应同时提供 `--source-review` 和 `--review`。输出包括新图谱、变化影响、语义失效清单、结构校验报告、更新后评审投影图谱和只含 READY 维度的测试设计输入。不提供评审参数时只能用于确定性变化诊断，不是正式测试生成入口。

失效是范围状态，不是全局停止开关：受影响切片在重新评审前不可使用；未受影响的已确认用例保留；新达到 READY 的切片追加生成用例。

## 安全降级

- 旧图谱不是Schema 1.4时停止，并先完成迁移/类型化。
- 旧图谱含 `visual_evidence` 或历史 `image_review` 新增事实时停止；必须显式保留或重新核验这些补充事实，不能静默丢失。
- 校验失败时不生成可下游消费声明。
- 本脚本不覆盖旧图谱，也不自动删除测试用例。
