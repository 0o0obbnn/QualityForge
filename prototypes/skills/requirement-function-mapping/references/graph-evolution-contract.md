# 图谱版本与变更影响契约

需求图谱是长期事实层，不因生成测试设计切片而被替代。每次需求版本形成独立快照；比较时使用稳定业务 ID，不以行号、章节序号或数组位置作为实体身份。

## 变化类型

- `ADDED`：新业务实体。
- `MODIFIED`：稳定实体的业务属性或规则发生变化。
- `DELETED`：旧实体在新快照中消失。
- `MOVED`：实体身份不变，只调整模块、父功能或业务对象归属。
- `RELATION_CHANGED`：依赖、包含、数据流、状态流、字段使用等边发生变化。

证据 locator 变化、生成时间变化和评审投影变化不单独构成业务需求变化。

## 影响传播

从直接变化节点沿有类型的图边计算有限深度影响：模块包含、功能包含、字段使用、依赖、引用、数据流和状态流。报告必须保留传播距离、上游节点和边类型。关联只表示“需要复核”，不自动断言业务一定受损。

当测试用例已接入图谱时，变化节点应继续沿 `verifies` 关系定位用例，并把用例标记为 `REVIEW_REQUIRED` 或 `RETEST_REQUIRED`，不得自动删除。图谱只保存测试用例索引；用例内容仍由测试用例产物维护。

## 执行

```bash
python3 scripts/compare_mapping_versions.py --before <旧图谱.json> --after <新图谱.json> --out <变更影响.json>
```

完成条件：新旧快照摘要存在；每个变化具有稳定实体 ID；所有影响节点具有距离和关系来源；`MOVED` 不误报为删除加新增。
